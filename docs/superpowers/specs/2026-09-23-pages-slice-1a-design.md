## 0. Цель и критерии успеха

Срез 1 концепции (§13) разрезан владельцем на два (§17, Р-2): **1а «Страница и шаблон»** — эта спека;
**1б «Оболочка и приложения»** — отдельная спека позже.

1а делает экран записи и собственные страницы владельца данными, а не кодом: страница — запись с
аспектом «страница», её тело — текст и блоки; любая запись показывается через шаблон; сегодняшний
экран записи становится шаблоном хоста. Параллельно закрывается последний прод-дефект промпта
(§С8-35 п. 3 спеки реформы) — индекс аспектов вместо дубля инструкций.

**Срез удался, когда:**

1. Владелец пишет страницу руками (например, «Утро»), открывает её по ссылке или из закреплённых — блоки
   показывают живые данные, всё окно уходит на сервер одним запросом за данными.
2. Любая запись открывается через шаблон; экран записи по составу совпадает с сегодняшним плюс теги,
   расхождения — только три намеренных (§8.2).
3. Шаблон владельца, объявленный для аспекта «проект», открывает проекты; спор двух шаблонов решается
   выбором владельца, и выбор запоминается.
4. В системном промпте чата и рутин ноль текстов `ai_instructions`; вместо них — индекс аспектов.

## 3. Аспект «страница»

### 3.1 Аспект

- `orbis/page` — встроенный, **ядро** (`module: null`).
- **Служебный в 1а** (`service: true`): тула `attach_orbis_page` нет, в индексе промпта (§10) его нет.
  Причина: авторство страниц агентом — срез 2 со своим промптом (концепция §8: каталог блоков в общий
  промпт чата не попадает). В срезе 2 аспект становится обычным. Интерфейс навешивает аспект своим
  путём (как сегодня навешивает `orbis/assignment`), не тулом модели.
- Навешенный аспект означает: запись показывается **своим телом** (§4, шаг 1), тело побеждает любой шаблон.
- Карточка аспекта «страница» собирается из реестра генерически, как все карточки (§7.3); нужен новый
  контрол «выбор нескольких аспектов».

### 3.2 Свойства (в 1а — два)

| Ключ | Подпись | Тип | Смысл |
|---|---|---|---|
| `orbis/template_for` | «Шаблон для» | `registry_ref {target: aspect}`, **список** | набор аспектов, записям с которыми подходит страница как шаблон. Пусто — просто страница; не пусто — шаблон, `this` в нём — показываемая запись |
| `orbis/template_wins_over` | «Главнее, чем» | `ref`, список, цель — записи с аспектом `orbis/page` | запомненные выборы в спорах (§4.3): «этот шаблон побеждает перечисленные» |

Правила (каталог Б-2):
- `template_wins_over` непуст → `template_for` непуст (победить в споре может только шаблон);
- ссылка на себя в `template_wins_over` запрещена.

Интерфейс, снимающий «Шаблон для» (шаблон становится черновиком), той же пачкой снимает и «Главнее, чем»:
иначе первое правило отвергло бы правку.

**Тип «список аспектов».** У ветки `registry_ref` сегодня нет сквозного конфига `cardinality`
(у `ref` и `select` он есть). Расширение — тот же сквозной конфиг, не новый kind. План сверяет его с правилом
словаря «форма встретилась ≥ 2 раза» (`packages/shared/src/registry/types.ts:4-5`). Второй потребитель формы —
манифест 1б («какие аспекты приложение читает»).

Дом, размещения, параметры, эталон (§4.1 концепции) — в 1а не заводятся (§15).

## 4. Выбор: чем показать запись

### 4.1 Решение владельца

«Запись не должна открываться шаблоном хоста, если есть другие подходящие шаблоны»; «при спорных —
предлагать выбрать и выбор запоминать»; запоминать **выбор для спора**, а не для записи (§17, Р-9).
Хранимого выбора на самой записи нет — концепция отвергла скрытое состояние на записи («главный аспект»),
и это остаётся в силе.

### 4.2 Алгоритм

Одна **чистая функция** в `@orbis/shared`: её вызывает любой клиент.

- **Вход:**
  - запись R: её аспекты A(R), признак «страница»;
  - список шаблонов владельца: страницы с непустым «шаблон для», без архивных. У каждого — `id`,
    набор S(t), `template_wins_over`, дата создания.
- **Выход:** своё тело | шаблон t | шаблон хоста; при споре — ещё список спорящих.

1. R несёт `orbis/page` → **своё тело** (показ; для шаблона — с плашкой предпросмотра, §9.3).
2. C = { t : S(t) ⊆ A(R) } — подходящие шаблоны.
3. C пусто → **шаблон хоста**.
4. M = шаблоны из C с наибольшим |S(t)|. |M| = 1 → он.
5. Иначе — спор. Победитель w ∈ M — тот, у кого «главнее, чем» покрывает всех остальных из M, и никто из M
   не объявлен главнее w. Есть такой w → **w**.
6. Победителя нет → показ **детерминированно**: раньше созданный из M (при равенстве — по `id`). Плюс
   плашка спора (§4.3).
7. Выбранный шаблон не разобрался (§5.8) → он исключается, выбор повторяется с шага 2. На экране плашка
   «шаблон „X“ не разобран: <причина>» со ссылкой на его настройку.
8. Не отрисовался даже шаблон хоста → **базовый вид записи** (§8.3).

Это правило концепции §5.3 («самый большой набор побеждает») с разрешением ничьей выбором владельца.
**Оно перерешает концепцию §6.2** («несколько или ни одного — шаблон хоста»). Правку концепции вносит
владелец ревизией (§16). Для 1б это значит: без приложения в адресе (чат, поиск) действует это же правило.

### 4.3 Спор и память

- **Плашка спора** на экране записи: «Для записей „проект + задача“ подходят два шаблона: [Шаблон проекта]
  [Шаблон задачи]. Какой использовать?» Подпись составляется из объединения наборов M.
- **Выбор x записывается одной пачкой с одним Undo:**
  - x.«главнее, чем» ∪= M \ {x};
  - из «главнее, чем» каждого m ∈ M убирается x (иначе получилось бы противоречие).
  Экран переключается сразу; плашка больше не появляется ни на этой записи, ни на других с тем же спором.
- **Новый участник спора** (в M появился шаблон, про который выбора нет) → шаг 5 не находит победителя →
  плашка спрашивает снова.
- **Противоречие**, внесённое мимо плашки (агентом или правкой свойства): A главнее B и B главнее A. Выбор
  при этом считается несделанным → плашка.
- **Смена выбора** — пункт «⋯» «Сменить выбор шаблона для таких записей»: та же плашка по требованию.
- Выбор хранится в данных графа (свойство шаблона). Поэтому он одинаков на всех устройствах и виден
  агенту и обратным ссылкам.

## 5. Грамматика тела v3

### 5.1 Принцип

**Второго формата нет** (концепция §4.2). Заметка, страница и шаблон пишутся одной грамматикой. Правда —
дерево документа (`body_doc`), текст (`body`) — его печать и каноническая форма для модели, диффа и
«Править как markdown». Все новые конструкции — семейства `{{…}}`: они стоят с начала строки, маркер
занимает свою строку, ключевые слова английские. Так уже устроен сегодняшний `{{query:…}}`.

Владелец отклонил компактную «блочную область» без скобок: это была бы вторая запись того же самого, а канон
всё равно одна форма. К вопросу вернёмся с фактами, если ручное написание шаблонов станет частым (§17, Р-16).

### 5.2 Контейнеры — у каждого открытия есть закрытие (Р-14)

```
{{columns}}
{{column}}
…текст и блоки…
{{/column}}
{{column}}
…
{{/column}}
{{/columns}}

{{tabs}}
{{tab: Запись}}
…
{{/tab}}
{{tab: Тред}}
…
{{/tab}}
{{/tabs}}
```

- Внутри контейнера — только его части (`column` / `tab`); текст вне части — ошибка.
- Вложенность контейнеров ≤ 2 (контейнер внутри части другого контейнера — и не глубже).
- Колонок 2–4, вкладок 1–8. Это умолчания, план вправе уточнить. На узком экране колонки встают
  одна под другой.

### 5.3 Блоки обвязки

Показывают запись `this` (§6.4).

| Блок | Показывает |
|---|---|
| `{{title}}` | эмодзи, заголовок с правкой, строка фактов по контрактам (сегодняшняя шапка экрана записи) |
| `{{tags}}` | теги с правкой |
| `{{body}}` | тело записи в редакторе (§6.2); **в шаблоне не больше одного** |
| `{{card: <аспект>}}` | карточка аспекта (ключ `orbis/goal` или подпись в кавычках, печать — ключом); ничего, если у записи его нет |
| `{{cards}}` | карточки всех аспектов записи, не размещённых шаблоном через `card:` |
| `{{subtasks}}` | подзадачи |
| `{{blockers}}` | блокировки |
| `{{backlinks}}` | обратные ссылки: связь «упоминает», упоминание в теле, ссылочное свойство |
| `{{versions}}` | закреплённые версии тела |
| `{{thread}}` | тред записи |

### 5.4 Блок данных и формы показа (Р-10, Р-13)

Настройки показа — в той же проекции запроса канона, где сегодня лежат `display` и `title`. Второй записи
настроек нет.

```
{{query: <запрос>, display=list}}
{{query: <запрос>, display=table, columns=[orbis/due_date, orbis/priority], hide_empty}}
{{query: <запрос>, display=tile, aggregate=sum(orbis/amount), title="Потрачено"}}
{{query: <запрос>, display=tile, aggregate=latest(orbis/weight), title="Вес"}}
```

| Ключ | Значения | Правило |
|---|---|---|
| `display` | `compact` (только заголовки, по умолчанию), `list` (строки как в Browser), `table`, `tile` | `display` из Q-AST сегодня рендером не читается — начинает читаться |
| `aggregate` | `count`, `sum(<свойство>)`, `latest(<свойство>)` | обязателен при `tile` и только при нём |
| `columns` | `[<свойство>, …]` | только при `table`; без него — колонки строки фактов по контрактам (Р-13) |
| `hide_empty` | флаг | прячет только честно пустой результат, не ошибку |
| `title`, `sortBy`, `limit` | как сегодня | — |

Списки пишутся в квадратных скобках, потому что запятая уже разделяет части запроса. Старые
`{{query:…}}` читаются как раньше.

### 5.5 Где работают блоки (Р-12)

| Что | Заметка | Страница | Шаблон |
|---|---|---|---|
| Текст, `{{query:…}}` | да | да | да |
| Контейнеры | **нет** (меню «/» не предлагает) | да | да |
| Блоки обвязки, кроме `{{body}}` | **нет** | да (`this` — сама страница) | да |
| `{{body}}` | нет | нет | да, не больше одного |

Причина: обычная запись и так показывается через шаблон со своими заголовком и карточками, и блок
обвязки в её теле дал бы второй экземпляр на том же экране. Контейнеры в заметке не показывались бы
раскладкой (§9.1). Если такой блок попал в заметку (вставкой, агентом), он не рисуется: на его месте
плашка «работает на страницах и в шаблонах — сделать запись страницей?», текст сохраняется.

### 5.6 Даты

Концепция §4.2: в теле страницы только относительные даты. **На страницах и в шаблонах** блок данных с
абсолютной датой — ошибка блока с подсказкой относительного токена. В заметках абсолютные даты разрешены:
заметка — документ, а не шаблон. Токены сегодня: `today`, `overdue`, `next_7d`, `after_7d`. Токены периодов
(«этот месяц») — 1б (§15).

### 5.7 Пространство имён

Примитивы хоста — без префикса (`{{title}}`, `{{query:…}}`). Компоненты приложений — `{{<приложение>/<имя>…}}`
(концепция §3.3, «питание/кольцо»). В 1а компонентов нет. Незнакомая форма `{{…}}` остаётся текстом, как
сегодня, — 1б принесёт `{{finance/…}}` без смены грамматики.

### 5.8 Ошибки разбора

Ни одна ошибка не теряет текст: конструкция сохраняется дословно (механизм `rawBlock`), на экране — плашка
с причиной:

- незакрытый контейнер или часть;
- текст вне части;
- глубина > 2;
- блок не на своём месте (§5.5);
- второй `{{body}}`;
- абсолютная дата на странице;
- незнакомое свойство или неразобранный запрос.

Шаблон с ошибкой в разборе считается не разобранным (§4.2, шаг 7).

### 5.9 Формат и копии правил

- `DOC_SCHEMA_VERSION` 2 → 3. Подъём v2 → v3 не меняет узлов. Старые вкладки браузера до перезагрузки
  получают отказ на сохранении, как при прошлом подъёме; черновики защищены действующим контрактом
  перештамповки.
- Дифф Ш1 видит контейнеры и их части как единицы (`TRANSPARENT_KINDS` и соседи).
- Новые узлы вносятся во все копии правил синхронно (разведка нашла их в нескольких местах, приложение А):
  - `KNOWN_NODE_TYPES`, `KNOWN_BLOCK`;
  - таблицы `strip-ids`;
  - разборщик первого кадра `bodySegments`;
  - регэкспы ссылок.
- **Проверка корпуса до выкатки:**
  - тела, где строка `{{…}}` после v3 станет блоком;
  - блоки с `display=table`, которые начнут рисоваться таблицей.
  Оба — посчитать и показать владельцу до прода.

## 6. Показ и данные

### 6.1 Два инструмента, одни блоки (Р-7)

- **Рендерер** — новый. Рисует тело на показ: текст, колонки и вкладки по-настоящему, блоки с данными.
  Им показываются страницы и шаблоны. Случайной правки нет.
- **Редактор** — сегодняшний. Им открыто тело записи (`{{body}}`), и им же настраиваются страницы (§9).
- Компоненты блоков одни и те же: рендерер ставит их напрямую, редактор — в свои узлы.

### 6.2 `{{body}}`

Вставляет на своё место редактор с телом записи `this` — сразу печатаемый, как сегодня. Вместе с ним
приходят первый кадр до загрузки редактора, плашки тела и предложения Ш1. Блоки тела (смарт-листы) рисует
этот редактор. В предпросмотре шаблона на выбранной записи (§9.3) тело **только для чтения**.

### 6.3 Единый механизм данных блоков (Р-11)

Любой блок данных — на странице, в шаблоне, в теле заметки, в предпросмотре редактора, в первом кадре —
получает данные одним способом: «результат моего запроса для этого `this`».

- **Клиент** собирает просьбы блоков, появившихся одновременно, в одну пачку. Блок, поправленный в редакторе,
  уходит пачкой из одного.
- **Сервер** исполняет пачку в одной транзакции под идентичностью владельца (права как у `entity.query`) и
  отдаёт по каждому блоку отдельно: строки / число / ошибку, а для списков — признак и число «ещё N».
- **Потолок пачки** — 30 блоков; план вправе уточнить. Строки блока ограничены его `limit` и потолком сервера.
- Агрегаты `count` / `sum` / `latest` — существующие компиляторы канона.
- Редактор заметок внешне и как инструмент письма **не меняется**; меняется только путь, которым смарт-лист
  получает данные. Это единственное касание заметок, его закрывают тесты на существующие смарт-листы.
- **Исключение, временно:** счётчики закреплённых записей в сайдбаре остаются отдельным вызовом — это
  прообраз размещений, 1б.

### 6.4 `this` и данные записи

| Где | `this` |
|---|---|
| шаблон | показываемая запись |
| страница | сама страница |
| предпросмотр шаблона | выбранная запись |
| тело записи внутри шаблона | эта запись |
| редактор при настройке | запись, чьё тело настраивается |

Данные для блоков обвязки — **один** запрос записи `this` (как сегодняшний `entity.get`). Он берёт только
включения, нужные блокам выбранного шаблона: нет `{{backlinks}}` — обратные ссылки не грузятся.

### 6.5 Ошибки, свежесть, скорость

- Ошибка блока видна плашкой с причиной («свойство „срок сдачи“ не найдено»); остальные блоки работают.
  Пустоты вместо ошибки не бывает.
- Свежесть — прежняя: после записи в граф — инвалидация тем же механизмом.
- Шаблон хоста лежит в поставке. Экран записи без своих шаблонов начинает рисоваться без лишнего запроса.
  Список шаблонов владельца (маленький) грузится один раз и обновляется при изменениях.

## 8. Экран записи как шаблон хоста

### 8.1 Текст шаблона хоста (Р-16)

```
{{title}}
{{tags}}
{{tabs}}
{{tab: Запись}}
{{card: orbis/goal}}
{{card: orbis/assignment}}
{{card: orbis/routine}}
{{card: orbis/agent-run}}
{{card: orbis/financial}}
{{body}}
{{/tab}}
{{tab: Детали}}
{{cards}}
{{versions}}
{{subtasks}}
{{blockers}}
{{backlinks}}
{{/tab}}
{{tab: Тред}}
{{thread}}
{{/tab}}
{{/tabs}}
```

Шаблон лежит текстом в коде поставки, разбирается тем же разборщиком и рисуется тем же рендерером, что шаблоны
владельца. В 1а он **не правится**; правка — 1б, копия с эталоном (Р-3).

### 8.2 Три намеренных отличия от сегодняшнего экрана

1. Заголовок и теги над вкладками и видны на любой вкладке (сегодня заголовок есть только на первой,
   тегов на экране нет).
2. Вкладка «Сущность» → «Запись» (словарь концепции).
3. Аспект со своей карточкой показывается одним куском на вкладке «Запись» над телом. Сегодня части
   разнесены: прогресс цели наверху, поля — в «Деталях»; ожидание тикета наверху, назначение — в «Деталях».

Всё остальное по составу совпадает. Любое другое расхождение — дефект.

### 8.3 Гарантии хоста (для любого шаблона)

- **Дописывание карточек** (концепция §5.3): карточка аспекта записи, не размещённая ни `{{card: X}}`, ни
  `{{cards}}`, дописывается в конец экрана.
- **Базовый вид записи** (концепция §3.2) — заголовок, тело, карточки, зашитые в код. Не шаблон, а последний
  резерв (§4.2, шаг 8).

### 8.4 Меню «⋯»

**У записи** — сегодняшние пункты (закрепить, архив, ссылка, закрепить версию, править как markdown) и новые:

| Пункт | Когда | Что делает |
|---|---|---|
| «Открыть через шаблон хоста» | запись открыта шаблоном владельца | разово, не запоминается |
| «Открыть через „X“» | подходят и другие шаблоны | разово |
| «Настроить шаблон „X“» | открыта шаблоном владельца | настройка шаблона с баннером (§9.2) — «изменить для всех» |
| «Изменить вид только этой записи» | запись не страница | «изменить только эту» (концепция §4.6), ниже |
| «Сменить выбор шаблона для таких записей» | запись спорная (§4.3) | плашка спора по требованию |
| «Сделать страницей» | запись не страница | навешивает `orbis/page`; тело становится экраном — для новых страниц (дашборд из пустой записи) |

**«Изменить вид только этой записи»** — одна пачка, один Undo. Текст текущего шаблона (своего или хоста)
копируется в тело записи, навешивается `orbis/page`. Судьба собственного текста записи — по трём случаям (Р-19):

1. **Текста у записи нет** → только копия шаблона.
2. **Текст есть, в шаблоне есть `{{body}}`** → текст встаёт на место `{{body}}`.
3. **Текст есть, а шаблон тело не показывает** (намеренно, например шаблон финансовой записи) → «как раньше» и
   сохранность текста одновременно невозможны. Спрашиваем:
   > В этом шаблоне текст записи не показывается, а у записи он есть. Что с ним сделать?
   > **[Сохранить версией и убрать]** · **[Показать внизу страницы]** · **[Отмена]**
   - «Сохранить версией» — текст уходит в закреплённую версию «Текст до изменения вида» (механизм версий
     тела); страница выглядит ровно как раньше; вернуть — «Открыть как запись → Детали → Версии».
     Пока текст лежит в версии, его не видят поиск и агент — это сказано в подсказке кнопки.
   - «Показать внизу» — текст остаётся в теле, в конце страницы; вид отличается от прежнего.

Молча дописывать или молча убирать текст нельзя. В случаях 1–2 запись выглядит как раньше, а раскладка теперь
своя. Ограничение: «Перестать быть страницей» у такой записи
оставит в теле блоки страницы — они покажутся плашками (§5.5). Сразу после действия его отменяет Undo.
«Вернуть вид по шаблону» — не 1а.

**У страницы:**
- «Настроить»;
- «Открыть как запись» (через шаблон хоста: версии, тред, обратные ссылки);
- «Сделать шаблоном для…» (ставит «Шаблон для»);
- «Предпросмотр на записи…»;
- «Перестать быть страницей».

## 9. Настройка

### 9.1 Редактор при настройке

«Настроить» открывает тело страницы или шаблона в том же редакторе, что у тела записи.

- **Контейнеры** показываются подписанными рамками одна под другой («Колонка 1», «Вкладка: Тред»).
  Раскладкой их рисует только показ. Настоящие колонки внутри редактора — позже (§15). Поэтому контейнеры
  и не предлагаются в заметках.
- **Блоки обвязки** — подписанные заглушки («[Заголовок записи]», «[Карточки аспектов]»), без живых данных.
- **Блоки данных** — живой предпросмотр (механизм §6.3).
- Новые блоки вставляются меню «/»; контейнеры и обвязка там только у страниц и шаблонов.
- «Готово» возвращает к показу.

### 9.2 Баннер шаблона

При настройке шаблона: «Вы правите шаблон — изменится вид всех записей с аспектом „проект“». Список аспектов
берётся из «Шаблон для».

### 9.3 Предпросмотр

Открытый шаблон показывается с плашкой «Шаблон для: проект · предпросмотр на: [запись ▾]».
- По умолчанию выбрана последняя изменённая подходящая запись; подходящих нет — `this` = сама страница.
- «Предпросмотр на записи…» в «⋯» страницы — то же для черновика шаблона (страницы без «Шаблон для»).
- Тело записи в предпросмотре — только чтение.

## 11. Принцип записи в граф и реестр отступлений (Р-15)

### 11.1 Принцип

Концепция: страница пишет в граф только действиями по имени (слой 3, срез 2).

**В 1а ничего нового не пишет в граф мимо действий.** Существующая правка экрана записи переносится как есть:
- заголовок, теги, тело, поля карточек;
- подзадачи, блокировки;
- действия своих карточек: назначить исполнителя, запустить рутину, откатить прогон, «план → факт».

На действия её переводит срез 2. Отсюда же отказ от чекбокса в строках списка на странице: он был бы новым
(Р-13). Блоки обвязки правят только свою запись `this` — это поведение примитивов хоста (концепция §3.2,
§9), а не страница, пишущая в граф.

### 11.2 Временные отступления от концепции

| Отступление | Снимается |
|---|---|
| Шаблон хоста — текст в коде, не данные, не правится | 1б — копия с эталоном |
| Контейнеры не предлагаются в заметках | позже — колонки в редакторе |
| Свои карточки аспектов — код хоста, а не компоненты приложений (П0: у Бюджета нет особых возможностей) | 1б — финансовая уходит в Бюджет; ярусы компонентов — позже |
| Существующая правка экрана записи мимо действий | срез 2 |
| Счётчики закреплённых — второй путь данных | 1б — размещения |
| Нижний ряд вкладок (`TabBar`) на телефоне при правиле «навигация никогда не внизу» | 1б — навигация |
| Слова кода вне словаря (`installedViews`, модули) | 1б; `Blocks` — в 1а |

### 11.3 Натяжение

Настройки показа хранятся в проекции запроса, хотя по концепции это свойства блока. Владелец принял ради одного
синтаксиса. Следствие: тот же запрос в туле `entity_query` их игнорирует.

## 12. Хранение, миграции, выкатка данных

- **Миграций БД, по дизайну, нет.** Аспект и свойства — строки сида реестра; значения — в `props` записей;

- Реестр: аспект №14 ломает пины «13 аспектов» (разведка, приложение А).
  Служебный аспект не даёт `attach_*` → эталон тулов не меняется.
