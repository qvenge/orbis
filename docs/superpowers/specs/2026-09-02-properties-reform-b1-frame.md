## §1. Гейт и веха I

Часть Б исполняется тремя срезами (§С9): **Б-1** контракты и подписки, **Б-2** язык E полностью / каталог правил / действия / классификатор, **Б-3** генератор промпта / поверхности реестра / экспорт / модульные гейты web.

**Гейт части Б — §С8-18 первой вехой Б-1** (ревизия 3): аспект, заведённый только декларацией — аспект, свойства и привязки `implements` к `money-movement`, `completable`, `when` — попадает в `spent` Budget, в Agenda, в строку списка M14 и под `excludeBlocked`; в диффе вехи нет ни одной строки кода под этот аспект (греп по key и id — ноль вне фикстуры и снимков). Веха не закрывается и следующие задачи не начинаются, пока сценарий не зелёный; провал — дефект движка, чинится в Б-1, сид и таблицы не откатываются (§А12-1).

Что разведка подтвердила про гейт:
- Пути заведения пользовательского аспекта в коде нет: единственный писатель `aspect_definitions` — тестовая фикстура `seedCustomAspect` (`apps/server/test/helpers.ts:131-158`), и она уже пишет `implements`. Веха I закрывается фикстурным сидом владельца, как и записано в ревизии 3; «живьём» через AI — после тулов вехи II и при живом ключе.
- Ни один из четырёх потребителей сегодня не читает подписку и не знает контрактов: Agenda — три текстовых запроса с клиента (`apps/web/src/features/agenda/useAgenda.ts:44,51,58`), Budget — код `apps/server/src/budget/aggregates.ts`, строка списка — цепочка `if` по аспекту (`NativeRow.tsx:209-246`), `excludeBlocked` — сахар из трёх констант (`packages/shared/src/query/parse-ast.ts:890/904/905`, `:921`) и поле `sourceNotIn` (`ast.ts:147,192-197`). Гейт проверяет ровно то, что все четыре стали читать реестр.
- Фикстура гейта — **два аспекта**: финансовый (money-movement + completable + when) и нефинансовый (только completable + when.moment) — второй нужен, чтобы строка M14 и `excludeBlocked` проверялись отдельно от Budget, и он же даёт фикстуру `SLOT_AMBIGUOUS` для §С8-21 (см. §4-2).

Пересчёт мест §С1-4 — информационный отчёт при закрытии Б-1 (три корзины против прогноза ≈ 445 / ≈ 180 / ≈ 17 из 642), не условие (§С8-14). Боевой фронт перевода посчитан разведкой: 62 боевых `= ANY(…aspects)` в сервере и три вызова `propsOf` (`aggregates.ts:323, :543, :590`); разнос по родам — работа отчёта, не гейта.

- **Р1.** Сид контрактов и подписок — тем же путём, что три реестра А (`db/seed-registries.ts`, механизм `'seed'`, source `'system'`), не через тулы. Цена: одна функция сида.

Цена: одна строка в двух компонентах (В-3 §8 — подтвердить видимое поведение).
- **Р5.** Agenda — одна подписка, один вызов, движок компилирует секции в один OR-запрос с тегом секции; `sortBy`/`limit`/«200+» — по секциям в движке. Цена: если один запрос не держит секции — движок разбивает на N запросов внутри той же tx, декларация не меняется.
- **Р6.** Карта классов дельты — третьим полем дельты аспекта, не расширением `selectOptionSchema`. Цена: одно поле.
- **Р7.** Кэш `spent`: обе половины версии в строке; undo — снос строк задетых конвертов (ленивый пересчёт), не инкремент по inverse; `relation_delete` `envelope-binding` — гейт `created_by` симметрично созданию; суточная граница — день `as_of` в ключе строки. Тип — `numeric`, `::text` на выходе. Цена: одна колонка / одна ветка каждое.
- **Р8.** Перф-гейт §С8-15 — `test:perf:volume` вне CI (гейт задач Budget и гейт среза), p95 на прогретом корпусе, холодный — записывается. Цена: минута на гейте вместо каждого пуша.

- **Р10.** Отказ «модуль выключен» — новый код `MODULE_DISABLED` (21-й, по образцу `RULE_CONFLICT`/`DEREF_IN_CONSTRAINT`), маска включённости — на поверхностях, не в `effectiveRegistry`. Цена: один код.
