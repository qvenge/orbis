## §1. Принцип: разрешимое ядро, один универсальный слой

**Формула.** Всё, что живёт в слое A (данные-декларации), принадлежит одному из пяти *родов* — запрос, вывод, ограничение, переход, представление — с **названной границей выразительности** и единым языком выражений (Б3). Внутри ядра **нет пути к универсальности**: рекурсия — только транзитивное замыкание одной роли с капом (Ч9); действие не вызывает действие; правила стратифицированы; второго языка выражений нет. Универсальность достижима только через **рутину** — единственный Тьюринг-полный слой, и он надзираемый (журнал, чекпойнты, пачка D42). Тьюринг-полнота, обнаруженная внутри ядра, — дефект, а не достижение.

**Почему не Тьюринг-полнота.** Тьюринг-полнота = «выразимо что угодно», и цена — теорема Райса: ни одно нетривиальное свойство такой программы не разрешимо (завершится ли, сколько стоит, что тронет, не противоречит ли другой). Ставка реформы (brief §1, шаг 3) — ровно на эти вопросы: декларацию можно *провалидировать, показать диффом, откатить*. Это возможно только у языков, которые не Тьюринг-полны по построению: SQL без рекурсии, Datalog, регулярные языки, формулы Excel до `LAMBDA`, формульный язык Salesforce, Foundry Actions. Случайная Тьюринг-полнота (CSS + HTML, PowerPoint, Magic: The Gathering) — известный класс аварий.

**Какое свойство вместо неё.** Прецедент — *реляционная полнота* Кодда (1972): язык запросов полон, если выражает всё, что выражает исчисление первого порядка над схемой, — не «что угодно», а *всё из названного класса*; SQL этим свойством обладает и при этом остаётся анализируемым. Наш аналог: пять родов, у каждого — граница (известный формализм) и конверт гарантий; полнота проверяется покрытием корпуса (568 мест инвентаря + R1–R32 + 10 правил делегирования из рулинга V2), конверт — каноническими отказами валидатора.

**Где Тьюринг-полнота нужна и живёт.** Рутина = LLM с тулами; универсальна по построению и потому под надзором (D35-В5 «пол безопасности», D42). Всё «если / пока / подумать» уходит туда (Ч11-доп п.5). Граница ядра и рутины — не деталь реализации, а инвариант архитектуры.

## §2. Паспорта родов

Формат паспорта: сигнатура · кирпичики · **граница** (формализм) · за границей (куда уходит) · гарантии конверта · обратимость · приёмка.

### Q — запрос

- **Сигнатура:** `State → Seq<Entity>` (упорядочено, с капом).
- **Кирпичики:** канонический AST В12 (дерево `and/or/not` над предикатами одной сущности: `props` по id, core-колонки, `tags`, членство в аспекте, `has(prop)`, `class(contract)`, диапазоны и date-токены); реляционные предикаты по **одной роли**: `children_of`/`parents_of`, `has_relation`/`has_children`, `descendants_of`/`ancestors_of via=<роль>` с капом глубины (Ч9); `excludeBlocked` как частный случай (`has_relation dependency` + класс ≠ `closed`); `search` (FTS); `sortBy`/`limit`.
- **Граница:** *булевы комбинации унарных предикатов над одной свободной сущностью + экзистенциальные условия по рёбрам одной роли, включая транзитивное замыкание одной роли с капом*. В терминах Datalog — стратифицированное отрицание, одна линейно-рекурсивная предикатная схема на роль, без агрегатов в теле; фрагмент FO(TC) с одной свободной переменной.
- **За границей (по построению):** соединения двух свободных сущностей («задачи, чей срок позже срока родителя») — только через *подъём* вычисляемым свойством (D: `nearest_ancestor`-класс) и затем E над своими props; агрегатные предикаты («проекты с > 3 открытых задач») — очередь 2 через `rollup` (D); рёбра и пути как результат (align Д1 — ручка движка линзы, код B); обход по нескольким ролям и поиск циклов из запроса (Ч9, граница С5); поиск по сходству — слой embeddings рядом (стилмен (б)).
- **Гарантии:** завершаемость (единственная рекурсия — замыкание с капом); безопасность результата (⊆ сущности владельца через RLS); стоимость — один SQL с ограниченным CTE; валидность решается при сохранении (типы по словарю kind'ов, существование поля/аспекта/роли по реестру — закрывает inv:152 «`aspect=` не валидируется»).
- **Обратимость:** не применимо (чтение).
- **Приёмка:** golden-корпус «AST → SQL → результат» (01 §6.2) + фикстуры *невыразимого* (соединение, две роли, агрегат в предикате) с ошибкой разбора, не пустотой (01 §6.4).

### D — вывод

- **Сигнатура:** `State → Value` (на сущность или на поверхность).
- **Кирпичики:** агрегаты над результатом Q — `sum/count/min/max/latest` по свойству + арифметика E над агрегатами (`spent`, `effective_limit = limit + carryover`, `remaining`, `daily_pace`, `unbudgeted` — Ч8); вычисляемые свойства по графу — шаблон `nearest_ancestor` → `orbis/parent_project`/`root_project` (Ч9); `progress_source` цели (уже подписка); очередь 2 — `backref`/`lookup`/`rollup` (ref Р9).
- **Граница:** *нерекурсивные представления над результатами Q с агрегацией и арифметикой E* — класс SQL-view, материализуемый (клапан §4.3). Вычисляемое свойство — кэш по правилу 3 §10: истина — рёбра/факты, пересчёт в той же tx, `model_writable: false` (Б6).
- **За границей:** рекуррентность по времени — rollover: `carry_n = f(remaining_{n-1})` — это рекурсия по периодам, в D недопустима «на лету»; допустима только как **T при переходе периода** (материализация значения в свойство конверта) — так она и реализована сегодня (`rolloverCreate` в `budget/aggregates.ts`), и так её описывает Ч8 (`rollover: {source, carry}` — декларация *перехода*, не вывода); итерации до неподвижной точки; вывод, читающий историю (журнал) как вход.
- **Гарантии:** детерминизм (одно состояние — одно значение); завершаемость; идемпотентность пересчёта (`D(state) = D(recompute(state))`); границы устаревания — «пересчёт в tx правки источника».
- **Обратимость:** нет inverse (Б6): undo правки источника триггерит пересчёт; отдельного отката вывода не существует.
- **Приёмка:** П2 (производительность агрегатов); тест идемпотентности пересчёта; фикстуры rollover как T.

### C — ограничение

- **Сигнатура:** `State → ok | Violation[]` (с именем правила и «отключить», Ч7 права).
- **Кирпичики:** типы свойств (закрытый словарь kind'ов В8 + границы); `required` на аспекте; `requires_when`/`forbidden_when` (E над своими props); `unique_among` (функциональная зависимость по набору свойств среди неархивных сущностей владельца); ограничения ролей — `target_max_incoming`, `acyclic`, контракты концов, `created_by`; валидность `ref` (членство в Q цели — ref Р4); полнота `value_map` (Б5); precondition CAS (равенство снимку); **`assign_level`** классификатора делегирования (рулинг V2: условие E → `молча/показать/обсудить/нельзя`) — ограничение особого рода: не «ok/нарушение», а «ok/уровень», но та же форма.
- **Граница:** *ограничения, проверяемые за одну транзакцию над затронутой сущностью, её рёбрами одной роли и результатом одного Q; условия — E.* Класс: denial constraints + функциональные зависимости + графовые ограничения одной роли. Важно: **`acyclic` для одной роли — внутри границы Q** (цикл ⇔ `source ∈ descendants_of(target) via role`); инвентарь M8 (inv:53) относил «всё графовое» к невыразимому — после Ч9 ацикличность одной роли выразима декларацией, в остатке C остаётся только *путь цикла в сообщении об ошибке* (01 §4.2 «A → B → C → A»).
- **За границей:** ограничения между двумя сущностями не через одну роль — только через подъём вычисляемым свойством (D) и затем E над своими props (`child.due ≤ parent_project.due` — законный паттерн); ограничения по сходству (дедуп: ±1 день + `counterparty` по сходству — остаток C, inv:85); темпоральные (по истории); межпользовательские.
- **Гарантии:** fail-closed на записи (brief §4-6); тотальность (E); стоимость — не более одного Q на графовое ограничение; ошибка называет правило и предлагает «отключить», не серую кнопку (Ч3).
- **Обратимость:** не применимо (проверка).
- **Приёмка:** golden-корпус «сущность → вердикт» (Р7) расширяется правилами: у каждого шаблона ≥ 1 позитивная и ≥ 1 негативная фикстура; «10 правил делегирования из дня мечты» выразимы без расширения каталога (рулинг V2).

### T — переход

- **Сигнатура:** `(State, Params) → State' | Reject`, с **inverse** у каждого применённого перехода (кроме системного пересчёта D — Б6).
- **Кирпичики:** тулы исполнителя (примитивы, стадии 1–7); действия Ч11 (`params` → `precondition` (C) → прямолинейные шаги → одна строка журнала, один inverse, один undo); правила-переходы — `on_enter_class` (проставить свойство), `default` (заполнить), `mirror_relation` (производное ребро), материализация повторов (детерминированные id, правило 2 §10), rollover при переходе периода; операции реестра — слияние с unmerge (Р10), дельта, `proposed`; вкл/выкл модуля.
- **Граница:** *прямолинейные программы над тулами с тотальными выражениями E: без циклов и ветвлений; «пакетное» = map по результату Q с капом; глубина вложенности действий — 0 (действие не вызывает действие).* Класс конечных, атомарных, детерминированных переходов с вычислимым inverse. Уровень подтверждения — функция политики от объединения фактов чувствительности шагов и декларации (Б2), никогда не поле декларации.
- **За границей:** поток управления, зависящий от состояния (`if`/`while`), ожидание, итерация до неподвижной точки → рутина; внешние и необратимые эффекты (V3) — *допустимы* в T только с фактами `external`/`irreversible` и честным «отката нет» в журнале (рулинг V3, стресс-тест).
- **Гарантии:** атомарность (01 §13 п.4); идемпотентность по id (batch_id); завершаемость (конечные шаги × кап результата Q); inverse существует ⇔ у всех шагов есть inverse, иначе переход объявлен необратимым до исполнения; уровень подтверждения вычисляется, не декларируется; гейты актора (allowed_tools, режим, скоуп) проверяют **резолвленные** шаги (Б2).
- **Обратимость:** `apply → undo` = состояние байт-в-байт (кроме D-кэшей, которые пересчитываются).
- **Приёмка:** golden «apply → undo → байт-в-байт» на каждый шаблон T; тест «действие с шагом вне `allowed_tools` актора → отказ» (запрет `batch_execute` рутинам в новой форме); фикстура «вложенное действие → отказ».

### V — представление

- **Сигнатура:** `State → Content` (секции × строки × слоты).
- **Кирпичики:** подписки Ч7/Ч8 — `sources` (Q + окно), `hide_when` (E), маппинг слотов через контракты, `counted_set` по именованным наборам классов, порядок совмещения M14; `offered_by` действий (на какой поверхности, при каком условии E).
- **Граница:** *собственной выразительности нет* — композиция Q/D/E + фиксированные рендер-атомы движка (код B). Подписка ссылается только на контракты и именованные наборы классов (Ч8) — никогда на аспекты и сырые значения.
- **За границей:** раскладка, новые рендер-атомы, вычисления в строке сверх D — код слоя B.
- **Гарантии:** движок без подписок честно пуст (Ч7); производитель и потребитель не знают друг о друге — это даёт консервативность (§3-9); детерминизм.
- **Обратимость:** правка подписки — T реестра (журнал, undo).
- **Приёмка:** снимки поверхностей на четырёх состояниях реестра (эталон / выключенный модуль / пользовательский аспект с привязкой / переименованный label — расширение В10 с промптов на поверхности).

### E — язык выражений (сквозной, Б3)

- **Где:** условия правил, `hide_when`/`offered_by.when`, `precondition`, формулы агрегатов и дефолтов, формула id материализации, условия классификатора V2. **Ровно один язык** — второй не заводится никогда.
- **Граница:** *тотальные функции первого порядка над одним контекстом* (класс total functional programming): значения — `props` сущности, параметры, контекст (`$today` в таймзоне владельца, `$owner`, `$entity`); операции — сравнения, decimal-арифметика (`budget/decimal.ts`), булева логика, `in`/членство в группе, `class(contract)`, `has(prop)`. Запрещены циклы, пользовательские функции, IO, недетерминизм. Каноническая форма — JSON-AST по JSON Schema; текст — сахар Р18.
- **Семантика отсутствия (нужно решить в спеке):** `has(p)` — единственный предикат присутствия; сравнение с отсутствующим значением — `false` (fail-closed), если у свойства нет `default` (В5); арифметика с отсутствующим — ошибка типизации при сохранении, не `null` в рантайме.
- **Гарантии:** типизация при сохранении по kind'ам; стоимость ≤ O(размер AST); детерминизм.
- **Приёмка:** фикстуры тайп-чекера; «бюджет» — самое большое допустимое выражение; тест «рекурсия/самоссылка невыразима синтаксически».

### P — паттерны fast-path (сквозной, M13)

- **Граница:** регулярные языки без обратных ссылок и lookahead — класс RE2 (линейное время по построению). В8 уже сделал этот выбор практически: `exclusiveMin` вместо lookahead в decimal «чинит экспорт в RE2/Go» — это и есть сохранение регулярности.
- **За границей:** контекстно-зависимый разбор реплики — остаток C (notes:340 «сам разбор»).
- **Приёмка:** валидатор отвергает паттерн вне RE2.

## §3. Сквозные свойства конверта

Две половины — выразительность (1–3) и разрешимость (4–10). Спека хороша, когда обе названы и не противоречат.

| № | Свойство | Формулировка | Как проверяется | Где сегодня нарушено / где всплыло |
|---|---|---|---|---|
| 1 | **Полнота относительно класса** | каждый род покрыт до названной границы; остаток C = объединение заграничных областей | тест покрытия §5: 568 мест + R1–R32 + 10 правил делегирования, без пустых клеток | inv M8 относил `acyclic` к невыразимому — после Ч9 это внутри Q (паспорт C) |
| 2 | **Замкнутость** | результат кирпичика пригоден на входе другого: Q → `ref.target`, `scope`, подписка, «действие к результатам запроса», `acyclic`; D → E, C, подписка | таблица пар «производитель → потребитель» в спеке; каждая пара — фикстура | Ч9 «результат — обычные сущности» — принцип, пары не перечислены |
| 3 | **Минимальный базис** | у каждой вещи один дом; каталог шаблонов — сахар над ядром из немногих форм; шаблон в каталоге ⇔ ≥ 2 экземпляра или generic по построению | таблица «шаблон → форма ядра → экземпляры в коде» | отчёт №13 (три дома у `default`), №19 (`unique_among`, `target_max_incoming` — по одному экземпляру) |
| 4 | **Тотальность** | каждая декларация определена на всех входах; неопределённое отвергается при записи, не в рантайме | тайп-чекер E; фикстуры §4 | Б3 принял; семантика отсутствия — открыта (паспорт E) |
| 5 | **Завершаемость и ограниченная стоимость** | рекурсия только в Q (замыкание с капом); E — O(размер); T — конечные шаги × кап; batch > 10 → подтверждение | синтаксически (нет конструкций рекурсии) + П2/П6 | Ч9 кап ~32; кап результата Q для «пакетного» T не назван |
| 6 | **Стратификация** | граф зависимостей деклараций (правило → свойство → правило → ребро → зеркало → подписка → действие) ацикличен; правило не пишет то, что читает в своём же страте | валидатор строит граф при каждой записи реестра; цикл → `REGISTRY_CYCLE` | главная защита от случайной универсальности; сегодня графа нет |
| 7 | **Конфлюэнтность** | порядок применения правил не влияет на результат: на одно (свойство, событие) — не более одного писателя, либо явный приоритет | property-тест: два порядка → одно состояние | `on_enter_class` и `default` на одном свойстве — приоритет не определён |
| 8 | **Обратимость** | у каждого T есть inverse (или переход объявлен необратимым до исполнения); D без inverse (Б6) | golden «apply → undo → байт-в-байт» на шаблон | отчёт №2 (действие = batch), №8 (unmerge) |
| 9 | **Консервативность расширения** | пользовательская декларация не меняет семантику встроенных — только добавляет; выключение модуля не меняет результат чужих подписок | снимки поверхностей и результатов сидовых Q на эталоне = снимки при добавлении пользовательских деклараций, не трогающих встроенные контракты | формальная версия «не навязывать» и условие marketplace D36; отчёт №22 |
| 10 | **Вычислимость зависимостей** | «кто на этом стоит» (Ч3 честные зависимости) = обратные рёбра графа §3-6, выводятся автоматически | UI зависимостей читает граф, не рукописный список | Ч3 сегодня описан как список |

## §5. Тест покрытия

**Процедура.** Каждое из 568 мест инвентаря, каждое правило R1–R32 и каждое из 10 правил делегирования (рулинг V2, из 05-mission §2) получает строку: `место → род (Q/D/C/T/V/E/P) → кирпичик | остаток C с названной границей, которую превышает`. Два класса провала: (а) место *внутри* границы рода, но кирпичиком не выразимо — дыра кирпичика; (б) место в остатке C *без* названной границы — спрятанный код. ## §6. Приёмка спеки по формальным свойствам

Нумерация продолжает 01-architecture §13; формулировки — как там: проверяемое действие → ожидаемый исход.

8. **Паспорта родов заполнены.** У каждого из Q/D/C/T/V/E/P в спеке названы граница, «за границей → куда», гарантии, обратимость. Пустая клетка — спека не принята.
9. **Покрытие без пустых клеток.** Таблица §5 заполнена для 568 мест + R1–R32 + 10 правил делегирования; остаток C равен объединению заграничных областей паспортов; ни одно место внутри границы не осталось кодом без записи «почему».
10. **Канонические отказы.** 18 фикстур §4 красные до валидатора реестра, зелёные после; каждая — структурированный код, не текст.
11. **Граф зависимостей строится и проверяется.** Валидатор строит граф §3-6 на каждой записи реестра; цикл → отказ; «честные зависимости» Ч3 читаются из графа, рукописного списка нет.
12. **Консервативность.** Снимки четырёх состояний реестра (В10) расширены на поверхности: добавление пользовательских деклараций, не трогающих встроенные контракты, не меняет ни одного сидового снимка.
13. **Обратимость по шаблонам.** На каждый шаблон T — golden «apply → undo → байт-в-байт» (D-кэши исключены из сравнения и пересчитаны).
14. **Один язык.** Греп-гейт по сидам и реестрам (аналог В9 п.2): ноль строковых формул вне JSON-AST E.
15. **Тьюринг-тест наоборот.** Попытка выразить каждым кирпичиком бесконечный цикл, самовызов, рекурсию и ветвление — все отвергнуты валидатором. Это и есть проверка принципа §1: внутри ядра нет пути к универсальности.

**Решения владельца при принятии (25.08, по рекомендациям контроллера):**
1. **Семантика отсутствия в E — как в паспорте:** `has(p)` — единственный предикат присутствия; сравнение с отсутствующим — `false` (fail-closed); арифметика с отсутствующим без `default` — ошибка типизации ПРИ СОХРАНЕНИИ декларации, не null в рантайме. (Не путать с UI: форма по реестру показывает незаполненные свойства аспекта пустыми — это М2/Ч2, отдельное и уже принятое.)
2. **Кап результата Q для «пакетного» T:** обязателен в декларации (отказ `BATCH_UNBOUNDED`, §4-18); дефолт 100; порог §7.10 «batch > 10 → подтверждение» действует поверх.
3. **Два писателя одного (свойство, событие) — отказ валидатора,** явного приоритета не существует: конфлюэнтность по построению; желание двух писателей = сигнал слить правила или развести свойства.
4. **`unique_among` и `target_max_incoming` остаются шаблонами** с пометкой «generic по построению» (§3-3 это допускает): параметрические ограничения класса `required`, не доменные формы.

**Заметка для спеки (несоответствие формы, не решения):** `ref.target` и `scope` в заметке о ref описаны строками запроса — по Р12 и §4-16 канон хранения — Q-AST, текст — сахар.
