# Второй LLM-провайдер (OpenAI) — дизайн

| Поле | Значение |
|---|---|
| Дата | 2026-08-06 |
| База | `main` `b87333a` (слайс 3 закрыт, роадмап пройден) |
| Повод | на счёте `ANTHROPIC_API_KEY` нет средств — **весь путь модели мёртв**: чат, CSV-импорт, память AI |
| Основание решений | проба на живом ключе, отчёт — `docs/superpowers/reviews/2026-08-06-openai-probe.md` |

## 1. Что решает эта работа

Единственная задача: **вернуть путь модели к жизни**, добавив OpenAI вторым провайдером,
не сломав Anthropic. PRD §7.7 объявляет мульти-провайдерность оставленным швом; шов
оказался лучше, чем описан, — `AnthropicProvider` построен на Vercel AI SDK (`ai@7.0.15`),
поэтому большая часть кода уже провайдеро-независима.

Всё остальное — вне объёма. Явно НЕ входит: диета бандла, верхние кандидаты бэклога фазы E,
валидация D23/D24 (это решение владельца, не работа), стриминг.

## 2. Что установила проба (кратко; подробности — в отчёте)

Пять кругов на живом ключе, модель `gpt-5.5`. Существенное:

1. **Схемы реестра принимаются** — все 19 тулов, включая единственный в реестре `anyOf`
   (`attach_orbis_goal.progress_source`). Опасение, ради которого проба затевалась, снято.
2. **Транспорт решает.** `@ai-sdk/openai` по умолчанию ходит в **Responses API**, а тот
   отвергает наши схемы при ЛЮБОЙ строгости: `regex lookaround is not supported` на
   `positiveDecimal` (`^(?!0+(\.0+)?$)…`, три тула). **Chat Completions принимает.**
3. **strict-режим не годится** — 13 тулов из 19 отвергнуты, причины механические
   (необязательные поля, `additionalProperties` у `z.record`), ни одна не про `anyOf`.
4. **Послушность хорошая:** обе ветви союза верны, чипы D19 приходят в каждом терминальном
   ходе и **разбираются настоящим `extractSuggestions` без правок** (проверено на дословных
   ответах модели), текстовый протокол `[tool_result:…]` понят.
5. **`gpt-5.4-mini` не годится в дефолт:** тройной `attach`, `orbis/financial` без
   обязательного `category_ref`, пропущенные чипы.
6. **CSV-импорт риск не подтвердил:** при потолке 1024 токена ответ занял 47 — правок не нужно.
7. **Найдены два дефекта, не связанных с провайдером** (Д1 `tags=`, Д2 дублирующий `attach`).

## 3. Архитектура

Сегодня `apps/server/src/llm/anthropic.ts` содержит два разных слоя в одном файле:
работу с AI SDK (маппинг `finishReason`, маппинг тулов, таймаут, один шаг `generateText`)
и знание про Anthropic (фабрика клиента, имя дефолтной модели). Второй провайдер разделяет их.

```
llm/types.ts        LLMProvider — интерфейс (+ новое поле modelId)
llm/ai-sdk.ts       НОВЫЙ. Всё провайдеро-независимое:
                      mapStopReason, mapSdkResult, toSdkTools, SdkResultSubset,
                      PROVIDER_TIMEOUT_MS, класс AiSdkProvider (один шаг generateText,
                      запрет system-сообщений в messages, таймаут, modelId)
llm/anthropic.ts    ТОНКИЙ. createAnthropic + DEFAULT_ANTHROPIC_MODEL + AnthropicProvider
llm/openai.ts       НОВЫЙ, ТОНКИЙ. createOpenAI + DEFAULT_OPENAI_MODEL + OpenAIProvider
llm/provider.ts     фабрика: + ветка 'openai', + OPENAI_API_KEY
llm/scripted.ts     + modelId = 'scripted'
```

Требование к расслоению: **поведение Anthropic не меняется ни на йоту**. Тест — существующие
`anthropic.test.ts` и `provider.test.ts` продолжают проверять то же самое; переезд ассертов
в файл рядом с переехавшим кодом допустим, ослабление — нет.

## 4. Решения

### Р1. Транспорт — только Chat Completions (`provider.chat(model)`)

Доказано пробой: Responses API отвергает три тула из девятнадцати безусловно.
**Цена:** не пользуемся возможностями Responses API (их нам сейчас и не нужно).
**Обязательство:** комментарий в `openai.ts` цитирует отказ дословно и называет три тула,
иначе первый «упрощающий» вызов до `provider(model)` вернёт отказ.

### Р2. strict-режим не включается

Привести схемы к strict = объявить обязательным всё необязательное = изменить схемы аспектов
= **пересев реестра на проде**. Взамен не даёт ничего: вход тула валидирует ajv по реестру
(01-architecture §3, стадия 2 исполнителя). **Цена:** аргументы тулов не гарантированы схемой
на стороне провайдера — ровно как сегодня с Anthropic.

### Р3. Имя модели приходит от провайдера, а не от дефолта чужого

`apps/server/src/ai/send-message.ts:91` сейчас считает имя модели как
`env.ORBIS_LLM_MODEL || DEFAULT_ANTHROPIC_MODEL` и отдельно опознаёт echo через
`instanceof EchoProvider`. При OpenAI без явной `ORBIS_LLM_MODEL` метеринг записал бы
`claude-sonnet-5` — то есть **счётчик расхода врал бы про модель**.

Решение: `LLMProvider` получает `readonly modelId: string`; `makeAiDeps` берёт
`provider.modelId`. `instanceof`-ветка исчезает. **Цена:** правка интерфейса с четырьмя
реализациями (Echo, Scripted, Anthropic, OpenAI) и тестовыми двойниками.

### Р4. Фабрика: неоднозначность — это отказ, а не молчаливый выбор

| `ORBIS_LLM_PROVIDER` | Ключи | Итог |
|---|---|---|
| `'anthropic'` | нет `ANTHROPIC_API_KEY` | ошибка (как сегодня) |
| `'openai'` | нет `OPENAI_API_KEY` | ошибка (симметрично) |
| `'echo'` | — | echo (как сегодня) |
| иное | — | ошибка, сообщение перечисляет все три (как сегодня, +openai) |
| не задан | ровно один ключ | этот провайдер |
| не задан | **оба ключа** | **ошибка**, сообщение называет оба и требует задать `ORBIS_LLM_PROVIDER` |
| не задан | ключей нет | echo в dev, ошибка в production (как сегодня) |

Ветка «оба ключа» — новая. Обоснование — доктрина самого файла: «молча отвечать заглушкой
и метерить её как echo хуже, чем не подняться». Молча выбрать один из двух живых провайдеров
(а сегодня Anthropic ещё и мёртв по балансу) — та же ошибка. **Цена:** локальный стенд, где
лежат оба ключа, не поднимется без явной переменной. Снимается тем, что `ORBIS_LLM_PROVIDER`
проставляется и в `apps/server/.env`, и в `.env.example`, а `render.yaml` задаёт её явно уже
сегодня.

### Р5. Дефолтная модель OpenAI — полноразмерная

`DEFAULT_OPENAI_MODEL = 'gpt-5.5'`. Обоснование — п. 5 пробы: mini даёт отказы исполнителя
(обязательный `category_ref` пропущен) и теряет чипы. **Цена:** дороже mini.
Переопределяется `ORBIS_LLM_MODEL`, как и у Anthropic.

### Р6. Промпт v4 — чинит Д1 и Д2

Carried-решение проекта: изменение текста промпта = **новый файл `vN` + новая фикстура**;
v3 остаётся замороженным артефактом. v4 = v3 плюс две правки:

- **Д1: `tags=` и `excludeTags=` в шпаргалку грамматики.** Слово `tags` встречается в v3
  **ноль раз**, хотя фильтр существует (`packages/shared/src/query/grammar.ts:66`) и является
  естественным способом выразить «доходы с тегом savings». Наблюдалось живьём: модель
  сочиняет `tag=`, грамматика отвергает («неизвестное поле 'tag'»), **цель молча приезжает
  без прогресса**. Дефект провайдеро-независимый: на Claude он такой же, просто проверить
  нечем.
- **Д2: запрет дублирующего `attach_<аспект>`** для аспекта, уже переданного в этом же
  `entity_create`. Модель делает и то, и другое; стоимость — лишний шаг из восьми и лишняя
  запись аудита, а `gpt-5.4-mini` дублирует трижды.

**Цена и риск:** промпт — общий для обоих провайдеров, а сравнить поведение Anthropic
до/после нечем (счёт пуст). Обе правки — добавление фактов и запрет лишнего действия,
не переформулировка существующих правил; это самый безопасный класс правки промпта.
Если Д2 окажется вредным, он снимается отдельно от Д1 — они независимы.

### Р7. Деплой без пересева реестра

Схемы аспектов не трогаются → **`bun scripts/seed-aspects.ts` не нужен**, `/health` дрейфа
не покажет. Меняется только окружение: `OPENAI_API_KEY` (`sync: false`) и
`ORBIS_LLM_PROVIDER: openai` в `render.yaml`. Отдельно: в `apps/server/.env.example` **нет
секции LLM вообще** — переменные документированы только в рунбуке; секция заводится.

## 6. Тесты

- Фабрика: по строке на каждую ветку таблицы Р4, включая новую «оба ключа → отказ».
- Маппинг (`ai-sdk.ts`): существующие ассерты `anthropic.test.ts` переезжают целиком;
  они и так гоняются на литеральных фикстурах формата SDK без сети.
- `openai.ts`: что провайдер построен на chat-транспорте и что `modelId` совпадает
  с запрошенной моделью. Сеть в CI не трогается — **Global Constraints плана 1b: CI гоняет
  только echo/scripted**, и это правило не нарушается.
- Промпт v4: фикстура байт-в-байт + гард D19 (пример маркера из текста промпта прогоняется
  через `extractSuggestions`, как это уже делает `v3.test.ts`) + тест, что `tags=` в тексте есть.
- `send-message`: метеринг пишет `provider.modelId`, а не дефолт Anthropic.

## 7. Приёмка (живой смоук, T7)

Локальный стенд, `ORBIS_LLM_PROVIDER=openai`, настоящий ключ, service worker снят
(`getRegistrations().unregister()` + `caches.delete`), сервер запускается **из `apps/server`**.

1. Чат отвечает вообще (сегодня — `SERVICE_UNAVAILABLE`).
2. «Хочу накопить 300000 на отпуск…» → одна сущность, аспект `orbis/goal` навешен,
   на detail видна полоса прогресса.
3. Чипы продолжений видны в ленте.
4. Запрос из `progress_source` **разбирается** — прогресс не `unsupported`.
5. Метеринг записал имя модели OpenAI, а не `claude-sonnet-5`.
6. CSV-импорт: analyze распознаёт колонки.
7. Консоль без ошибок.

## 8. Риски

- **Сравнить с Anthropic нечем.** Счёт пуст, поэтому «поведение Anthropic не изменилось»
  доказывается только тестами и чтением кода, не прогоном. Названо прямо, не замазано.
- **Транспортное ограничение Р1 хрупко к версии SDK.** Если `@ai-sdk/openai` изменит
  дефолт или Responses API снимет проверку регекспов, комментарий протухнет. Митигация —
  комментарий цитирует ошибку дословно, воспроизводится скриптом пробы за минуту.
- **Правка промпта затрагивает и Anthropic.** См. Р6: класс правки самый безопасный,
  Д2 отделим от Д1.
- **Владелец АФК.** Все решения приняты контроллером и помечены `Р<N>` — ждут валидации,
  как D23/D24 фазы E.
