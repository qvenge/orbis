## 1. Словарь

| Термин | Значение |
|---|---|
| **Хост** | сам Orbis: граф, реестры, канон запросов, AI, журнал, Undo, доверенный UI, каталог примитивов, рантайм приложений |
| **Запись** | узел графа |
| **Аспект** | интерпретация записи («это задача»); у аспекта есть **шаблон по умолчанию** и **карточка аспекта** |
| **Приложение** | набор деклараций из семи элементов (§3.2) по одному публичному контракту; хост — «нулевое приложение» |
| **Манифест** | элемент приложения: идентичность и разрешения |
| **Страница** | запись с аспектом «страница»; открывается своим телом |
| **Тело** | документ записи: дерево узлов из текста и блоков |
| **Блок** | узел тела: подписка + форма показа + настройки; данных не содержит |
| **Контейнер** | блок, содержащий блоки: колонки, вкладки |
| **Вкладки** | контейнер в теле; переключают содержимое внутри одной открытой страницы |
| **Примитив** | блок из стандартной библиотеки хоста |
| **Компонент** | блок, который приносит приложение: ярус 1 — композиция примитивов декларацией; ярус 2 — код в песочнице |
| **Карточка аспекта** | блок, показывающий данные аспекта на записи: по умолчанию собран из реестра, приложение может спроектировать свой |
| **Шаблон** | страница с параметром `this` (запись), объявляющая набор аспектов, для которых подходит |
| **Параметр** | ручка страницы, меняющая показ, но не граф; типизирован реестром |
| **Оболочка** | элемент приложения: идентичность, домашняя, навигация, экран записи |
| **Навигация** | список размещений в оболочке; на десктопе сайдбар; **никогда не внизу экрана** |
| **Размещение** | ярлык: что (страница / запрос), в каком приложении, где, на какой позиции; может нести значения параметров |
| **Рамка** | то, что хост рисует вокруг содержимого: присутствие хоста, шапка (необязательна), навигация |
| **Шапка** | необязательный элемент рамки с именем экрана и контролами параметров |
| **Присутствие хоста** | минимальный доверенный элемент рамки: «назад», меню «⋯», доверенные плашки |
| **Дом** | приложение, в рамке которого открывается страница |
| **Адрес** | приложение + цель (страница или запись) + параметры; у каждого места есть адрес |
| **История** | стек адресов с состоянием экранов; «назад» ведёт по ней |
| **Эталон** | версия страницы или оболочки, с которой приложение её принесло; «вернуть как было» и обновления сравнивают с ним |
| **Действие** | именованный рецепт из реестра; конвейер мутаций, подтверждение по риску, журнал, Undo |
| **Рутина** | действие агента во времени |

Понятия, которых в концепции **нет**: view, модуль, FAB, уровень, пространство, режим, секция, панель, главный аспект.

## 2. Суть в четырёх фразах

1. **Модель работает в момент авторства, рендер детерминированный.** Агент собирает страницу один раз по просьбе; результат хранится версионируемым артефактом (не кэшем); дальше рисуется без модели. Сборка — платно (D36), рендер и ручная правка — бесплатно.
2. **Страница — запись с аспектом «страница»; её схема — её тело.** Второго формата схем нет; текст — каноническая форма.
3. **Приложение — семь элементов по одному контракту.** «View» и «модуль» растворяются в нём.
4. **П0: у наших приложений нет особых возможностей.** Хост и приложение различаются только доверием, никогда — API. Проверка: «может ли пользовательское приложение целиком заменить наш Бюджет?» — обязано быть «да».

## 3. Семь слоёв, хост и приложение

### 3.1 Семь слоёв системы

```
┌───────────────────────────────────────────────────────────────┐
│ 7. Агент (хост): чат, рутины, память, исполнитель               │  пишет страницы,
│    приложение приносит сюда рутины и инструкции аспектов        │  зовёт действия
├───────────────────────────────────────────────────────────────┤
│ 6. Оболочка: идентичность, домашняя, навигация, экран записи    │  ГДЕ показать
├───────────────────────────────────────────────────────────────┤
│ 5. Страницы: записи с аспектом «страница», тело = текст + блоки │  композиция
├───────────────────────────────────────────────────────────────┤
│ 4. Блоки: примитивы хоста + компоненты приложений; каталог общий│  КАК показать
├───────────────────────────────────────────────────────────────┤
│ 3. Действия: именованные рецепты, конвейер, журнал, Undo        │  ЧТО можно сделать
├───────────────────────────────────────────────────────────────┤
│ 2. Словарь: свойства, аспекты, роли связей, контракты, привязки │  ЧТО значат данные
├───────────────────────────────────────────────────────────────┤
│ 1. Граф: записи и связи (страницы тоже записи)                  │  данные
└───────────────────────────────────────────────────────────────┘
```

Это слои **системы**, не приложения. Хост держит все семь и рантайм. Приложение приносит
строки в слои 2–7 по одному контракту; агент как таковой принадлежит хосту, приложение
приносит в седьмой слой только свои рутины и инструкции своих аспектов.

### 3.2 Хост — только то, что обязано быть доверенным

- Граф, реестры, канон запросов, RLS.
- Агент: чат, рутины, память, исполнитель; журнал, Undo, классификатор; **доверенный UI**:
  плашки подтверждений, экран установки приложения, присутствие хоста в рамке.
- **Стандартная библиотека примитивов** (состав — открытый вопрос §12): список, таблица,
  плитка, кольцо, график, календарная сетка, прогресс, контролы форм, контейнеры; **блоки
  обвязки записи**: заголовок, теги, карточки аспектов, подзадачи, обратные ссылки, тред.
- Рантайм: рендер страниц и рамок, песочница компонентов, переключатель приложений,
  глобальный поиск, настройки аккаунта, marketplace.
- Две гарантии сверх рамки: **базовый вид записи** (заголовок, тело, карточки аспектов —
  не шаблон, а последний резерв, если шаблоны испорчены) и **лимит глубины встраивания**.

Всё остальное — приложения, включая обзор записей и наши Бюджет / Повестку / Питание.

### 3.3 Приложение — семь элементов

| # | Элемент | Что это | Пример (Питание) |
|---|---|---|---|
| 1 | **Манифест** | идентичность (имя, иконка, акцент) + разрешения: какие аспекты и контракты читает, какие действия зовёт, нужна ли сеть до своего сервера, размер бандла | читает «приём пищи», «продукт»; зовёт «записать приём пищи»; сети нет |
| 2 | **Словарь** | свойства, аспекты, роли связей, контракты, привязки `implements` | аспект «приём пищи», свойство «калории»; «приём пищи implements „когда"» |
| 3 | **Действия** | именованные рецепты над `this` или без него | «записать приём пищи», «повторить вчерашний завтрак» |
| 4 | **Компоненты** | ярус 1 — композиция примитивов декларацией; ярус 2 — код в песочнице; пространство имён приложения, версия = версия приложения; **экспорт в общий каталог**; сюда же **карточки аспектов** и **шаблоны** как компоненты | «питание/кольцо» = примитив «кольцо» + подписка «сумма калорий за сегодня» |
| 5 | **Страницы** | записи с аспектом «страница»; копируются пользователю при включении со ссылкой на эталон | «Сегодня», «Дневник», «Продукты», «Статистика» |
| 6 | **Оболочка** | идентичность в рамке; домашняя; навигация (список размещений); экран записи: упорядоченный список «аспект → шаблон» и «аспект → карточка» | домашняя «Сегодня»; навигация из четырёх страниц; шаблон «приёма пищи» |
| 7 | **Рутины и инструкции** | рутины приложения, `ai_instructions` его аспектов | «недельный отчёт» пишет блок в «Статистику» |

Выключение приложения убирает все семь; данные остаются читаемыми; его блоки на чужих
страницах показывают плашку «приложение выключено» с кнопкой включить — никогда пустоту.

### 3.4 П0 — у наших приложений нет особых возможностей

Любая возможность, которой пользуется наше приложение, доступна пользовательскому через
тот же контракт. Различие только в доверии: подпись, проверка, предустановка.

1. Граница хост/приложение — список §3.2; всё, что не в нём, — приложение.
2. Наши приложения объявляют манифест с первого дня и идут через тот же конвейер действий,
   журнал и подтверждения.
3. Наши компоненты — ярус 1 по умолчанию; «особенное» — либо примитив хоста, доступный всем,
   либо ярус 2. **Прочтение строгое (В1, 2026-09-13): наш код яруса 2 исполняется в той же
   песочнице, что чужой.** Это заставляет сделать песочницу и библиотеку примитивов хорошими.
4. Пользовательское приложение вправе назначить свои шаблоны по умолчанию для аспектов
   Бюджета — так оно и заменяет наш Бюджет целиком.

## 4. Страница

### 4.1 Определение

Страница — запись с аспектом «страница». По хранению от заметки не отличается, и это
намеренно: «это задача», «это расход», «это страница». Аспект добавляет:

- **дом** — приложение, в рамке которого страница открывается; для пользовательской —
  назначенное владельцем, по умолчанию хост;
- **параметры** (§4.4) и, если есть `this`, роль **шаблона** (§5.3);
- **размещения**;
- **показ своим телом** — без обвязки записи; «открыть как запись» в
  меню «⋯» показывает ту же запись через шаблон хоста: версии, тред, обратные ссылки;
- **эталон** — для страниц от приложения.

Аспекты складываются: конкретный проект может сам быть страницей, если его телу навесили
аспект «страница»; тогда его тело побеждает шаблон. Снял аспект — снова запись.

### 4.2 Тело: текст и блоки — соседи

Дерево узлов, где текст и блоки на равных правах (модель Notion): заголовок, абзац,
список, виджет запроса, плитка, форма, контейнер колонок с абзацами и виджетами внутри.
Дашборд — документ с малым числом абзацев; заметка — с малым числом виджетов.

**Схема = тело.** Агент пишет страницу текстом с грамматикой блоков, как любую заметку;
второго формата нет. Текст — каноническая форма: легко генерировать, проверять, показывать
диффом с правкой до принятия (Ш1), править руками. Контейнеры — блочный синтаксис с
открывающим и закрывающим маркером, глубина вложенности ≤ 2. Вкладки — контейнер в теле,
и только там.

```
# Утро
Сначала важное, потом деньги.
{{columns}}
  {{col}} {{query: задачи, срок=сегодня, не сделано, сортировка=приоритет}}
  {{col}} {{tile: конверт «Еда», остаток за неделю}}
{{/columns}}
{{query: заметки, связаны с this=проект «Переезд», последние 3}}
```

Требования к телу: блок хранит запрос, не данные; относительные токены дат, никогда
абсолютные; страница компилируется в одну пачку запросов.

### 4.3 Состав: пять слоёв страницы

| Слой | Суть | Пример просьбы | Статус |
|---|---|---|---|
| 1. Композиция блоков | окна в граф + раскладка; только чтение | «утренняя страница: задачи на сегодня, остаток конверта, три заметки по проекту» | принято |
| 2. Параметры и шаблоны | ручки, не меняющие граф; страница «для записи» с `this` | «страница расходов с выбором месяца»; «у каждого проекта своя страница» | принято |
| 3. Формы и действия | страница пишет в граф только действиями по имени: кнопки в блоках, формы | «форма: сумма, категория, кнопка „записать расход"» | принято |
| 4. Оболочка | набор страниц приложения, навигация, домашняя, экран записи | «сделай „Утро" домашней, Бюджет убери из навигации» | принято, как оболочка приложения |
| 5. Логика | закрытый набор (§4.5) | «блок „Просрочено" только если есть просроченные» | принято (В2) |

### 4.4 Параметры

Параметр — ручка страницы, меняющая показ и не трогающая граф. Тип из реестра, поэтому
контрол выбирается сам: период даёт выбор месяца, запись даёт пикер с фильтром по аспекту,
выбор из списка даёт переключатель. Есть значение по умолчанию. Блоки ссылаются на параметр
по имени: «расходы за $период». В теле хранятся имя, тип и умолчание; текущее значение —
состояние просмотра, в историю входит, в тело не пишется. Размещение может нести готовое
значение: пункт навигации «Расходы: прошлый месяц».

Пример: страница «Расходы за месяц», параметр «месяц» (период, по умолчанию текущий), три
блока с «$месяц»; переключил месяц — все три пересчитались.

Особый параметр — `this`: «запись, о которой эта страница». Страница со `this` — шаблон
(§5.3). В шаблоне могут быть и обычные параметры сверх `this`.

### 4.5 Логика: закрытый набор

Правило: **страница показывает, блок считает, рутина реагирует.** В теле допустимы ровно
три конструкции.

- **Скрыть при пустом результате** — флаг на блоке; булев, над собственными данными блока.
- **Порог на блоке** — плитка, кольцо, прогресс принимают пороги как настройку («предупреждение
  при 80 %»); смысл порога знает сам блок.
- **Агрегаты канона** — плитка = агрегат над запросом; считает канон запросов.

Не допускаются: произвольные выражения, сравнения полей, ссылки блока на блок, вычисляемые
колонки. Выходы за пределы набора: новый блок приложения («дневной лимит» считает внутри
себя); расширение канона новым агрегатом (дорога хоста); рутина («если потрачено больше
80 % — напомни» — реакция во времени, не условие страницы). Многие «если» закрываются
параметрами без логики («показывать сделанные» — переключатель, привязанный к фильтру).

### 4.6 Страница и запись на экране

Разница только в том, через что рисуется содержимое. **Запись без аспекта «страница» всегда
показывается через шаблон**; обвязка записи — заголовок, теги, карточки аспектов, подзадачи,
обратные ссылки, тред — это блоки стандартной библиотеки, а сегодняшний экран записи —
шаблон хоста по умолчанию. Страница показывается своим телом.

Открыта страница «Сегодня» (телефон, Питание):

```
┌──────────────────────────────┐
│ ‹  Сегодня               ⋯   │  шапка (необязательна): имя страницы; «‹» и «⋯» — присутствие хоста
├──────────────────────────────┤
│  ◯ 1 240 / 2 000 ккал        │  тело: блок «кольцо»
│  Белки ▓▓▓░  Жиры ▓▓░░       │  блок «полоски макросов»
│  Завтрак   овсянка     350   │  блок запроса: приёмы пищи сегодня
│  Обед      суп         420   │
│  [ Записать приём пищи ]     │  кнопка действия — блок в теле
└──────────────────────────────┘
```

Открыта запись «Переезд» через шаблон Проектов:

```
┌──────────────────────────────┐
│ ‹  Проект                ⋯   │
├──────────────────────────────┤
│ Переезд                      │  блок «заголовок» — шаблон его включил
│ #дом #2026                   │  блок «теги»
│ Срок 30.09 · Бюджет 120 000  │  карточка аспекта «проект»
│ Задачи │ Доска │ Бюджет      │  вкладки — контейнер в теле шаблона
│ ☐ Заказать грузчиков         │
│ ☐ Собрать коробки            │
│ Запись │ Тред                │  тоже вкладки в теле
└──────────────────────────────┘
```

Открыта заметка через шаблон хоста по умолчанию:

```
┌──────────────────────────────┐
│ ‹  Запись                ⋯   │
├──────────────────────────────┤
│ Идеи для отпуска             │  заголовок, редактируемый
│ #отпуск                      │  теги
│ Текст заметки…               │  тело
│ Аспекты: +                   │  карточки аспектов
│ Обратные ссылки (2)          │
└──────────────────────────────┘
```

Второй и третий экран различаются только шаблоном; первый — тем, что содержимое есть
собственное тело страницы. Режим настройки страницы — тот же редактор, что у тела записи,
плюс лист свойств аспекта «страница»: параметры, дом, размещения. Два глагола правки
обязаны различаться на экране: «изменить для всех проектов» правит шаблон (с баннером «вы
правите шаблон»), «изменить только эту» создаёт собственную страницу записи.

## 5. Блок, карточка аспекта, шаблон, оболочка, рамка

### 5.1 Блок

Блок = подписка (запрос или подписка на контракт) + форма показа + настройки. **Блок никогда
не содержит данных.** Подписчик — блок, не «поверхность»; страница — контейнер подписчиков.
Блок привязан к **контракту** («когда», «движение денег»), а не к аспекту: календарь на
«Утре» показывает обеды рядом с задачами, как только Питание объявило привязку. Блоки всех
включённых приложений образуют **один каталог**; стиль — токены дизайн-системы хоста, акцент
приложения красит только рамку. Форма показа (таблица, доска, календарь над одним запросом)
— свойство блока. Блок — та же вещь на любой поверхности: на странице, карточкой в чате, в
уведомлении (В8; детали — §12).

### 5.2 Карточка аспекта

Блок, показывающий данные аспекта на записи: по умолчанию собран из реестра автоматически
(поля по типам свойств, правка на месте, «снять аспект»); приложение-хозяин аспекта вправе
спроектировать свой (вкладки «Подзадачи | Доска | Бюджет» у проекта). Объявляется в элементе
оболочки «экран записи»: «аспект → карточка». Экспортируется в каталог: чужой шаблон может
поставить `{{card: расход}}` у себя.

### 5.3 Шаблон

Страница с параметром `this`, объявляющая **набор аспектов**, для которых подходит:
«задача», «проект», «проект + задача». Один шаблон — сто рендеров. В теле шаблона два
особых блока: `{{card: X}}` — карточка конкретного аспекта, если он есть у записи, иначе
ничего; `{{cards}}` — карточки всех остальных аспектов записи, которые шаблон не разместил
сам. **Гарантия хоста: карточка аспекта, не размещённая шаблоном, дописывается в конец
экрана** — ни один аспект не бывает невидимым.

Пример шаблона «задача» из Проектов, покрывающий и «проект + задача»:

```
{{title}} {{tags}}
{{card: задача}}      срок, приоритет, блокировки
{{card: проект}}      вкладки «Подзадачи | Доска | Бюджет» — только если запись ещё и проект
{{cards}}             расход, заметка, что угодно от других приложений
{{backlinks}}
```

**Шаблон по умолчанию у аспекта** — изначально шаблон приложения-хозяина; пользователь
вправе назначить другой, в том числе из стороннего приложения (так пользовательское
приложение заменяет Бюджет). Хранимого «главного аспекта» у записи **нет** — понятие
отвергнуто как скрытое состояние.

**Выбор шаблона для записи** (§6.2): по приложению из адреса и его списку «аспект → шаблон»;
среди подходящих (набор аспектов шаблона ⊆ аспекты записи) побеждает самый большой набор;
при равенстве — порядок в оболочке; иначе шаблон хоста, который через `{{cards}}` и так
показывает всё.

Замечание к моделированию (уровень приложения, не концепции): если в приложении большинство
записей несут и «проект», и «задачу», это сигнал, что они — один аспект с иерархией, как в
Linear и Jira. Концепция работает в обоих вариантах.

### 5.4 Размещение и навигация

Размещение — ярлык: что (страница или запрос), в каком приложении, где, на какой позиции;
может нести значения параметров. Страница одна, ярлыков много; страница без размещений
достижима адресом. Размещение хранится у страницы, поэтому агент делает его обычной правкой
записи. Размещённый запрос даёт живой раздел навигации: «Проекты» — запрос «активные
проекты», строка ведёт на запись через шаблон.

Навигация — список размещений в оболочке. На десктопе — сайдбар. На телефоне — не внизу;
где именно (шапка, меню, домашняя) — дизайн-бриф. Внизу экрана навигации нет: переходы
между разделами одной страницы — вкладки в теле.

### 5.5 Оболочка

Декларация приложения: идентичность в рамке; домашняя; навигация; экран записи —
упорядоченные списки «аспект → шаблон» и «аспект → карточка» (порядок = разрешение ничьей
при выборе шаблона). Личная настройка — правки поверх; оболочка и страницы копируются
пользователю при включении со ссылкой на эталон (В3): «вернуть как было» и обновление
приложения при правленой странице — предложение агента «принять дифф?». Пользователь может
собрать **своё приложение** из своих страниц: та же декларация, без эталона.

### 5.6 Рамка

Хост владеет не шапкой, а **гарантиями**: выход («назад» по истории), меню «⋯», доверенные
плашки поверх любого содержимого. Форма присутствия хоста — жест и рукоятка на телефоне,
рейка на десктопе — дизайн-бриф. Шапка — необязательный элемент оболочки: приложение
включает по умолчанию, страница вправе убрать (тренировка идёт, сканирование чека,
дашборд на стене); тогда имя и параметры живут в теле блоками (В7). Рамка = присутствие
хоста + шапка (если есть) + навигация (на десктопе). Постоянное в рамке принадлежит
приложению, контекстное — странице: имя экрана, контролы параметров, пункты меню «⋯».

Действия без динамического тулбара (§11) живут в теле: кнопки и формы в блоках, действия
внутри карточек аспектов, пункты меню «⋯».

## 6. Адрес, переходы, история

### 6.1 Адрес

Адрес = приложение + цель (страница или запись) + параметры (включая `this`). У каждого
места есть адрес; история — стек адресов с состоянием экрана (вкладка, параметры,
прокрутка); глубокие ссылки и «поделиться экраном» — из адреса.

### 6.2 Правило дома и раскрытие адреса

- Страница открывается в рамке своего **дома**. Дом один; ярлыки в других приложениях —
  ссылки, помечены «↗ Питание». Бездомная страница, положенная в навигацию приложения,
  получает его как дом; **первое размещение задаёт дом**, каждое следующее — ярлык.
- Запись открывается **по адресу**. Приложение в адресе есть: его список «аспект → шаблон»,
  выбор по §5.3. Приложения в адресе нет (чат, поиск, чужая заметка): ровно один аспект
  записи имеет шаблон по умолчанию — он; несколько или ни одного — шаблон хоста (все
  карточки через `{{cards}}` и кнопки «открыть в Проектах», «открыть в Бюджете»).
- Ссылка внутри страниц приложения по умолчанию несёт это приложение, если у него есть
  шаблон для какого-то аспекта цели; иначе адрес раскрывается по правилам выше.

Отвергнуто: «рамка зависит от маршрута» (неявный вывод из истории). Адрес несёт приложение
**явно**.

### 6.3 Переходы: что переносится

Переход — открытие адреса. Переносится только приложение (по правилу ссылки выше).
**Не переносятся**: `this` (открыл задачу — `this` стал задачей), параметры (если ссылка их
не передала явно), состояние предыдущего экрана (оно в истории). **Контекст из графа, не из
маршрута**: шаблон задачи показывает «проект: Переезд» из связи в графе, и одна и та же
задача, открытая из проекта, из поиска и из чата, выглядит одинаково. Встроенные страницы
внутри одного экрана получают `this` и параметры открытой страницы — они содержимое.

Цепочка: Проекты, список → тап «Переезд» → адрес «Проекты / Переезд», шаблон проекта →
тап по задаче → «Проекты / задача», шаблон задачи, блок «проект» из графа показывает
Переезд → тап по расходу «Грузчики 12 000» → у Проектов нет шаблона расхода, адрес
раскрывается в «Бюджет / расход», рамка Бюджет → назад: задача → назад: Переезд на той же
вкладке → назад: список.

### 6.4 Встраивание

Страница может встраивать страницу (со `this` и параметрами открытой). Глубина ≤ 2,
самовстраивание запрещено, хост ловит цикл (шаблон проекта встраивает «страницу проекта»,
та — шаблон проекта).

## 7. Доверие, компоненты, производительность

### 7.1 Модель браузерных расширений

| Слой в браузере | В Orbis |
|---|---|
| Изоляция: код расширения в своём мире, к DOM через посредника | компонент яруса 2 исполняется в песочнице; данные приходят результатом подписки блока, к графу напрямую не ходит |
| Манифест разрешений при установке; «только на этом сайте / по клику» | манифест: какие аспекты и контракты читает, какие действия зовёт, нужна ли сеть; экран установки как экран согласия OAuth-гранта (D34); аналог «по клику» — доступ только к `this` открытой страницы |
| Опосредованный API | мутации только действиями по имени через общий конвейер; своей мутации у компонента нет |
| Никакого удалённого кода | пакет подписан, CSP запрещает догрузку; версия компонента = версия приложения |
| Магазин: проверка, подпись, рубильник | marketplace проверяет и подписывает; рубильник = выключение приложения с плашкой на месте блоков |
| Видимость | значок приложения на компоненте; в журнале у действия автор-приложение; права сужаются по наблюдениям (В6) |
| Доверенный UI: запрос разрешений рисует браузер | подтверждения, установка, присутствие хоста рисует хост; компонент только просит |

Инциденты случаются и у браузеров: остаточный риск принимается и держится рубильником;
фундамент — изоляция и опосредованный API, не доверие проверяющему. Песочница не решает
обман через интерфейс — его решает доверенный UI. Два яруса компонентов для всех приложений,
включая наши (В1): декларация по умолчанию, код в песочнице — законный второй ярус.

### 7.2 Экспорт и загрузка (В4)

Компоненты приложений экспортируются в общий каталог. Пачкой они не грузятся, потому что
«компонент» — три разные вещи:

- **каталог** — декларации (имя, схема свойств, контракты, инструкция агенту): маленькие
  данные, загружаются все, нужны редактору и агенту;
- **ярус 1** — композиция примитивов: кода нет, примитивы уже загружены;
- **ярус 2** — код: грузится лениво при первом рендере страницы, где он стоит; **песочница
  одна на приложение**, поднимается при первом использовании, гасится по бездействию.

Рендер страницы: список блоков → набор компонентов → недостающие грузятся параллельно, на
месте скелетоны (прогрессивный рендер). Манифест объявляет размер бандла, marketplace держит
лимит, хост измеряет загрузку и показывает на карточке приложения. Библиотека примитивов
хоста тоже режется на части. От числа установленных приложений зависят размер словаря и
подмножество каталога в промпте авторства; рендер зависит только от того, что на экране.

## 8. Агент в этой картине

- **Авторство.** Вход: просьба + каталог блоков + инструкции приложения + подмножество
  реестра под запрос. Выход: тело страницы текстом. Проверка: разбор → компиляция каждого
  запроса → сухой рендер по реестру (незнакомое свойство — отказ, не пустота). Доставка:
  предложение диффом с правкой до принятия (Ш1). Промпт авторства отдельный; каталог в общий
  промпт чата не попадает (проба P1).
- **Сопровождение.** Сломанный блок — сигнал; агент предлагает починку диффом. Обновление
  приложения при правленой странице — предложение «принять дифф?».
- **Рутины** действуют во времени, страницы — на экране. Рутина пишет блоки в страницу или
  предлагает правку. Инструкции аспектов и правила памяти влияют на авторство и разбор ввода, не на
  рендер.
- **Экономика (D36):** сборка страницы — платно; рендер и ручная правка — бесплатно;
  страница — данные владельца, экспортируемые.
- **Модель никогда не рисует в рантайме.**

| Сценарий | Что ломается | Правило |

## 11. Отложено: динамический тулбар

**Решение владельца 2026-09-13: делать без него.** Идея записана, чтобы не потерять.

Тулбар — плавающая панель действий поверх содержимого (на телефоне точно). Обсуждённая
модель: список действий из реестра; держатели — оболочка (по умолчанию) и страница
(переопределение: свой список / добавить / скрыть); действию передаются `this` и параметры;
главное действие — выделенный пункт. Для записи с несколькими аспектами сборка по тому же
правилу, что содержимое: действия шаблона → действия размещённых карточек аспектов в порядке
размещения → действия неразмещённых карточек под «⋯» (гарантия, что ничего не пропало) →
тулбар приложения по умолчанию, если никто ничего не дал; дубли по имени схлопываются;
видимы первые N. Не склеилось: владение тулбаром при переходах и при нескольких аспектах
ощущалось перегруженным. До возврата к теме действия живут в теле (§5.6).

## 12. Открытые вопросы

- **Состав стандартной библиотеки примитивов** первого состава (В9) — обсудить; список
  предложу отдельно.
- **Блоки в чате и уведомлениях** — направление принято (В8); отдельный разговор о том, как
  карточки чата становятся блоками и что с ними при отсутствии сети.
- Дизайн-бриф, не концепция: навигация на телефоне (шапка / меню / домашняя); форма
  присутствия хоста; экран установки по манифесту; запоминать ли последнее значение
  параметра.
- Уровень приложения, не концепции: «проект» и «задача» — один аспект с иерархией или два.

Сознательно вне рамки: совместная работа и роли (§10 продукта как было); marketplace как
процесс (проверка, выплаты); порядок реализации.
