# Шаблон промпта планировщика среза

Как пользоваться: заполнить `{{плейсхолдеры}}`, готовый экземпляр положить в леджер среза
(`.superpowers/sdd/<дата>-<срез>/planner-prompt.md`) и отдать новой сессии с чистым контекстом.
Шаблон под срез не редактировать — улучшения ехать сюда отдельным docs-коммитом, чтобы следующий
срез их унаследовал. Промпт не пересказывает спеку: состав, правила и приёмка живут в ней, здесь —
только как писать план. Собран 27.09.2026 из промптов срезов Г, 1а и 1б.

---

```
Напиши план исполнения среза {{название среза}} в {{абсолютный путь к репозиторию}}.

ИСТОЧНИК ИСТИНЫ
{{путь к спеке}} ({{ревизия}}, принята владельцем). Прочитай целиком до первого действия. Состав,
правила, границы и приёмка — в спеке; этот промпт их не пересказывает, при расхождении права спека.
Решения владельца {{Р-1…Р-N}} ({{где протокол с отвергнутыми вариантами}}) закрыты — не переоткрывай.
Не правь спеку, {{родительские документы: концепция, спеки прошлых срезов}}, PRD, 03-pending:
расхождение спеки с кодом — в раздел плана «Эрраты спеки» с адресом и предложенной правкой.

ПРЕДПОСЫЛКИ
- Спека в git: `git log --oneline -1 -- {{путь к спеке}}`. Нет коммита — стоп, спроси владельца.
- Разведка спеки снята на {{хеш}}. Первым делом `git log --oneline {{хеш}}..HEAD`; если HEAD ушёл —
  `git diff --stat {{хеш}}..HEAD` и перепроверь только задетые факты.
- {{Правки документов, которые владелец вносит отдельно: какие задачи от них зависят — план помечает
  их предусловием с проверкой в первом шаге задачи}}.
- {{Что сознательно вне среза}}.

ЧТО УЖЕ ИЗВЕСТНО — НЕ РАЗВЕДЫВАТЬ ЗАНОВО
Опирайся на проверенные факты, а не на свежий обход кода:
- разведка спеки: {{пути}};
- ревью спеки: {{пути}} — разделы «Что проверено и подтвердилось» и адреса в находках;
- передача и факты исполнения прошлого среза: {{пути к handoff, facts.md}}.
Сверх этого разведывай только то, чего там нет и без чего шаг не написать, — прежде всего
{{раздел спеки «открыто для плана»}}{{; пробы: список проб, если нужны}}.

РАЗВЕДКА — ЧИТАТЕЛИ
Точечное проверяй сам. Читатель-сабагент — когда нужен объём. Форму выбирай под нужду; качество плана
ради экономии не жертвуй:
- зона — когда по области пишется много шагов и нужен связный конспект (файлы, вызовы, тесты, пины);
- вопросы — когда нужны отдельные факты.
Одновременно — не больше двух читателей; зоны и вопросы не пересекаются; каждому — пакет: что уже
известно (пути), что установить, куда записать конспект. «Прочитай всё» не поручай.

РЕЗУЛЬТАТ
- План: docs/superpowers/plans/<дата>-{{срез}}.md, метод superpowers:writing-plans. Леджер (вне git) —
  {{путь к леджеру}}: facts-plan.md (факты и рулинги плана РП-N), progress.md, черновики.
- Образец формы — {{путь к последнему плану}}; читай только {{диапазоны строк: сквозные разделы, одна
  задача как образец шагов, закрытие и прод, эрраты и маппинги}}.
- Разделы плана: «Что установила разведка HEAD», решения плана РП-N, «Вопросы владельцу» с
  умолчаниями, «Предусловия владельца», глобальные ограничения, карта файлов, порядок и параллельность,
  задачи с TDD-шагами и мутационной проверкой сторожей, «Эрраты спеки», самопроверка и три маппинга без
  пустых строк: (а) нормативные утверждения спеки → задача и шаг; (б) приёмка → задача и шаг;
  (в) «открыто для плана» → где решено.
- Требование спеки в шаге — ссылкой на §, не пересказом. Задач столько, сколько нужно; промежуточные
  состояния между задачами не ломают рабочий путь.
- Первая задача — {{какая и почему}}. Предпоследняя — финальное ревью ветки и фикс-волна. Последняя —
  прод-процедура с жёсткой остановкой перед ней, только вместе с владельцем{{: пересев, перевод данных,
  особенности среза}}.
- Задача закрытия кладёт в леджер {{handoff-файл}} — факты для автора следующей спеки: {{что именно}}.

ЛОВУШКИ ИСПОЛНЕНИЯ — В «ГЛОБАЛЬНЫЕ ОГРАНИЧЕНИЯ» ПЛАНА
Перенеси из глобальных ограничений последнего плана и facts.md исполнения последнего среза то, что
действует. Минимум: `git commit -m "…" -- <пути>`; новые файлы `git add` до прогона сторожей на
`git grep`; `bun run test`, не голый `bun test`, вывод в файл, без `| head`, после сабагента — `ps` на
зомби; в серверных тестах `await freshGraph()`; пересев реестра ДО кода; ветку можно пушить ради CI,
мерж в main — один раз готовым срезом и вместе с владельцем; гейт-ревью задачи и финальное ревью ветки —
Opus 5.5, Fable 5.1 — второй линзой.{{ Ловушки этого среза.}}

МОДЕЛИ, АГЕНТЫ, ТОКЕНЫ
- Сабагенты — только самый последний Opus (сейчас Opus 5.5, model: opus); ID модели сверяй по ответу
  сабагента — ниже последнего Opus результат не принимается; sonnet и haiku — никогда.
- Черновики задач пишешь сам. Сабагенты-черновики — когда план большой (ориентир — больше 20 задач): не
  больше двух, на непересекающиеся кластеры, каждому пакет фактов из леджера; повторной разведки им не
  поручай.
- Параллельно не запускай агентов, читающих одни и те же файлы: у каждого своя зона, свои вопросы или
  своя линза.

РЕВЬЮ ПЛАНА — ДВЕ ЛИНЗЫ, ТОЛЬКО ЧТЕНИЕ, ПАРАЛЛЕЛЬНО
- Линза 1 — Opus 5.5 (model: opus): соответствие спеке и решениям владельца, полнота трёх маппингов,
  выполнимость каждой приёмки, порядок без сломанных промежуточных состояний.
- Линза 2 — Fable 5.1 (model: fable): исполнимость шагов — адреса file:line, команды, тесты, ловушки,
  скрытые цены.
- Каждому ревьюеру — один пакет (план, спека, пути к фактам леджера) и правило: по коду проверяй то, что
  утверждает план; факты леджера не переразведывай без сомнения. Своих выводов не передавай. Ответ:
  вердикт одной строкой → находки Critical / Important / Minor с доказательством и правкой; отчёт — в
  леджер.
- Находки проверяешь по коду и правишь сам; ложные отклоняешь с записью в facts-plan.md. Ре-ревью —
  одним агентом: возобнови ревьюера линзы, у которой больше Important (нового не заводи); он сверяет
  только правки. В докладе назови ID моделей ревьюеров из их ответов.

ГРАНИЦЫ
Не исполняй план, не создавай ветку, не правь код и документы из «Источника истины». Стоп и вопрос
владельцу — только если (а) разведка опровергла факт, на котором стоят две и более задачи, и спека
становится неисполнимой; (б) нужна миграция БД, которой спека не предусматривает. Остальное решай сам,
рулинг — в facts-plan.md.

ГОТОВО И ЗАКРЫТИЕ
Готово = план написан, самопроверка и три маппинга без пустых строк, ревью двумя линзами и ре-ревью
закрыты. Затем:
1. коммит плана в main локально: `git commit -m "docs(plan): {{срез}} — план исполнения (N задач)" --
   docs/superpowers/plans/<файл>`;
2. пуш — только по отдельной команде владельца.
Доклад владельцу простыми словами: число задач и шагов, эрраты спеки, вопросы с умолчаниями,
предусловия и привязанные к ним задачи, оценка объёма исполнения. Исполнение — только отдельным словом
владельца, в новой сессии, по промпту оркестратора (шаблон docs/superpowers/templates/orchestrator-prompt.md).
```
