## Что это

**A2UI** (Agent-to-User Interface; `a2ui.org`, `github.com/a2ui-project/a2ui`, Apache-2.0) —
«a protocol for agent-driven interfaces»: агент присылает **не HTML и не код, а JSON-описание
интерфейса** из компонентов, которые клиент заранее объявил в своём каталоге; клиент рисует их
своими нативными компонентами. Тезис анонса Google (12.2025): «We needed a way to transmit UI
that is **safe like data, but expressive like code**». Начат Google, дописан CopilotKit и
сообществом; переехал из `google/A2UI` в собственную организацию.

### Модель протокола (v1.0)

- **Surface** — единица UI с `surfaceId`, каталогом по умолчанию, моделью данных и **плоским
  списком компонентов** (adjacency list: каждый компонент — `{id, component, ...props,
  children: [ids]}`; дерево собирается по ссылкам от `root`). Плоский список выбран ради
  стриминга: рендер начинается, как только есть `root`, отсутствующие ссылки — заглушки.
- **Четыре сообщения агент → клиент:** `createSurface`, `updateComponents`, `updateDataModel`
  (адрес — JSON Pointer, upsert, `null` удаляет), `deleteSurface`. **Клиент → агент:** `action
  {name, context}`, где в `context` кладутся привязки к данным (`{"path": "/formData/email"}`).
- **Данные отдельно от структуры.** Свойства принимают литерал, `{path}` или вызов функции
  (`formatString`, `formatDate`, `pluralize`, `and/or/not`…). Инпуты — **двусторонняя
  локальная привязка**: правка мгновенно меняет локальную модель, **агент узнаёт о ней только
  по action** (кнопка, сабмит); флаг `sendDataModel` прикладывает всю модель к каждому action.
- **Шаблоны над списками:** `children: {path: "/items", componentId: "row_tpl"}` с
  относительными путями внутри элемента и `@index()`.
- **`checks`** — правила валидации на компоненте (`required`, `regex`, `email`, `length`,
  `numeric`), исполняются на клиенте; при провале интерактивные компоненты **отключаются**.
- **Каталог** — JSON Schema с полем `instructions` («design principles for LLMs»),
  `allowedParents`/`allowedChildren` на компонентах, у функций — `allowedCallers:
  rendererOnly | agentOnly | rendererOrAgent`, проверяется рендерером в рантайме
  (`INVALID_FUNCTION_CALL`). Базовый каталог: 18 компонентов (Text, Image, Icon, Video,
  AudioPlayer, Row, Column, List, Card, Tabs, Divider, Modal, Button, CheckBox, TextField,
  DateTimeInput, ChoicePicker, Slider) и 15 функций.
- **Доступность** — стандартные `accessibility: {label, description, live, hidden}` на любом
  компоненте, рендерер обязан маппить в ARIA/Semantics.

### Урок v0.8 → v0.9, который они признали сами

v0.8 строился на строгом structured output; по их словам, «LLMs kept breaking on complex nested
structures at scale». v0.9 — «prompt-first»: схема, правила каталога и few-shot примеры
кладутся **в системный промпт**, модель генерирует свободно, валидатор ловит ошибки, агент
самоисправляется до отправки клиенту («prompt-generate-validate loop»).

### Позиционирование против соседей (их таблица, сжато)

| | A2UI | MCP Apps | AG-UI |
|---|---|---|---|
| Подход | декларативный чертёж из компонентов | готовый HTML по `ui://` | транспорт бэкенд ↔ фронтенд |
| Рендер | нативные компоненты хоста | sandboxed iframe | что напишет разработчик |
| Стиль | **хост**, наследует дизайн-систему | **сервер**, изолирован | разработчик |
| Генерация LLM | ✅ рассчитан на стриминг | ❌ собран сервером заранее | через A2UI |
| Кросс-платформа | web, mobile, desktop, native | web (iframe) | протокол агностичен |

Собственная рекомендация Google (пост «A2UI + MCP Apps»): нативный рендер декларации — для
форм, данных и стандартных контролов; iframe MCP Apps — «for highly tailored, complex
experiences».

## Использовать напрямую? Три точки входа и вердикт по каждой

**А. Чат: модель рисует ответ через A2UI вместо карточек.** — **Нет.** Карточки Orbis — не
«что модель хочет показать», а «что система сделала или спрашивает»: их поля — `pendingId`,
`runId`, `undoActionId`, снятые предусловия, — выводятся из журнала и очереди решений, и судьбу
единицы карточка читает с сервера. Отдать модели композицию UI значило бы: (1) положить в
каждый промпт схему каталога с примерами — ровно то, чего проба P1 позволить не может;
(2) добавить петлю «сгенерировал → провалидировал → перегенерировал» на каждую реплику, за
токены владельца (D36 «AI платно»); (3) допустить, что диалог подтверждения нарисован моделью
— а подтверждение обязано быть детерминированной проекцией payload'а («исполняется ровно то,
что показали», §7.10). Главное достоинство A2UI — прогрессивный рендер стрима — в чате Orbis
некому использовать: стриминга нет (§10). Агентного SDK для TypeScript у проекта нет.

**Б. MCP-сервер отдаёт карточки как `application/a2ui+json`, чтобы внешние хосты рисовали их
нативно.** — **Не сейчас; шов дешёвый.** Свидетельств, что хосты Anthropic (Claude Desktop,
claude.ai, Claude Code) рендерят A2UI из результата тула, не нашлось — там стандарт MCP Apps
(`ui://`, iframe). Единственный MCP-клиент сегодня — локальный Claude Code (рулинг 23.08).
Когда хост появится, цена — **один сериализатор** над существующим union карточек рядом с
текстом; протокол в ядро не въезжает.

**В. Констелляция и marketplace: сторонние виды как декларации в каталоге хоста.** — **Самое
интересное совпадение; решение отложить до проектирования marketplace.** §10 записывает
«iframe-изоляция сторонних views» — A2UI построен как ответ на ровно эту дилемму: iframe даёт
изоляцию ценой «visual dissonance» и веб-привязки, декларация в каталоге хоста — дизайн-систему
хоста, отсутствие песочницы и один и тот же вид на web и в будущей нативной оболочке
(§10 «Platform Bridge», мобильная поверхность V3). Это и есть недостающая половина шва «одна
декларация — все поверхности»: сегодня аспект даёт данные, тул и карточку, **но не вид**
(раунд 4, bb). Оговорка по существу: A2UI — протокол **рантайма** (сообщения, surfaces,
стриминг); Orbis'у для вида из декларации нужен **формат** (компоненты + привязки к данным),
а не транспорт. Брать формат без рантайма — так делает Vercel json-render.

**Итог:** как зависимость и как протокол — не сегодня; как **формат декларативного вида** для
сторонних модулей — кандидат под D36, когда дойдёт до marketplace; как MCP-привязка — шов.

## Идеи к перенятию

### И1. Вопрос рутины — формой по реестру, а не строкой с четырьмя кнопками

**Что у них.** Инпуты с двусторонней локальной привязкой, `checks` из каталога, кнопка
отключена, пока проверки не прошли, агент получает **готовую модель данных** только по action.

**Что у нас.** `orbis_ask` несёт вопрос и до четырёх готовых ответов строками; ответ владельца
— строка или индекс. Формы по типу свойства из реестра **уже есть** (query-блок, карточки
аспектов), валидация из реестра — `value-schema.ts`.

**Что взять.** Расширить контракт `orbis_ask` необязательным описанием **полей ответа**
(список `{property_id | core-поле, обязательность}`): контрол выбирает реестр по типу свойства,
как в форме query-блока, проверки — `value-schema`, ответ — объект, а не строка. Тогда рутина
спрашивает «на какую дату перенести?» с датапикером и «сколько?» с суммой, а не «ответь
текстом». Текстовое представление ответа обязано оставаться носителем в истории следующего
прогона (карточка — указатель, текст — «без сети»).
**Адрес-кандидат:** 01-architecture §9.3 (контракт `orbis_ask`), `QuestionCardData`, D42 ОЧ.5.
**Цена:** новая ветка формы в `QuestionCard` над уже существующим реестровым выбором контрола;
схема ответа — в `askJsonSchema`. Не для Б-1.

### И2. Сторонний вид = декларация в каталоге хоста; iframe — только для длинного хвоста

**Что у них.** Каталог как allowlist: «Agents can only use pre-approved components from your
catalog — no UI injection attacks»; стиль наследуется от хоста; сравнение с MCP Apps и
собственная рекомендация «нативно — стандартное, iframe — highly tailored».

**Что у нас.** §10: «iframe-изоляция сторонних views» без альтернативы; шов D35 без формата
вида; «вид из декларации должен рождаться приличным» (карта работ).

**Что взять.** Переформулировать пункт §10: по умолчанию сторонний модуль приносит **вид
декларацией** в каталоге Orbis (плоский список компонентов + привязки к данным подписки по
JSON Pointer), рисуемый нашей дизайн-системой на web и в нативной оболочке; iframe — исключение
для несводимого к каталогу. Формат-кандидат — совместимый с A2UI/json-render JSON, чтобы позже
тот же вид мог прислать и агент. Решать при проектировании marketplace, не раньше.
**Адрес-кандидат:** 00-product §10 (строка про iframe), D36, шов «одна декларация — все
поверхности» (рамка D35).
**Уточнение 2026-09-12:** идея конкретизирована концепцией страниц и приложений —
`specs/2026-09-11-pages-and-apps-concept.md` (§2.2 компоненты двух ярусов, §5 модель
доверия «как расширения браузера», П0 «у наших приложений нет особых возможностей»).

### И3. Один документ каталога вместо двух зеркальных union'ов

**Что у них.** Каталог — один JSON Schema-документ, по которому валидируют обе стороны;
рендерер терпим к неизвестному.

**Что у нас.** Union карточек продублирован руками в сервере и web с комментарием «обязаны
ДОСЛОВНО совпадать… типы намеренно не общие»; терпимость рендера к неизвестному `kind` уже
есть. Причина, по которой типы намеренно не общие, в комментарии не названа.

**Что взять.** Малая форма: одна схема карточек в `packages/shared/src/contracts` (рядом с
`tools.ts`) как источник обоих типов и валидатор `metadata.cards` при чтении ленты; правило
«неизвестное → текст» остаётся. Если причина раздельности — эволюция сервера впереди web, она
обслуживается версией схемы, а не двумя копиями. **Опровергаемо:** сначала выяснить причину у
владельца.
**Адрес-кандидат:** `apps/server/src/tools/registry.ts`, `apps/web/src/features/chat/cards/types.ts`.

### И4. Стриминг ответа — плоским списком с ранним корнем

**Что у них.** Рендер начинается, как только определён `root`; отсутствующие ссылки — заглушки;
неразрешённые привязки во время стрима — пустые значения.

**Что у нас.** Стриминг чата — пункт §10 без дизайна; карточки собираются после завершения
прогона (`send-message.ts`, шаг 5).

**Что взять.** Когда §10 «Стриминг ответов чата» дойдёт до спеки — правило «корень первым,
заглушки вместо недостающего, пустота вместо неразрешённого» как готовый дизайн стрима
карточек, а не только текста. Низкий приоритет.
**Адрес-кандидат:** 00-product §10 → будущая спека стриминга.

## Подтверждения (ничего не менять, отметить сходимость)

- **П1. Prompt-first = D29 и проба P1.** Google отказался от строгого structured output для
  вложенных UI-схем по той же причине, по которой Orbis поставил `strict:false` (D29); а их
  необходимость класть схему и примеры в каждый промпт — ровно тот бюджет, которого у Orbis
  нет (проба P1). Выбор «UI выводится из результата тула, а не рисуется моделью» — подтверждён
  чужим отступлением.
- **П2. «Safe like data».** Карточки как данные закрытого union'а с терпимым рендером — тезис
  безопасности A2UI; у Orbis с первого слайса.
- **П3. «Агент узнаёт по action».** Двусторонняя локальная привязка с синхронизацией только по
  действию — та же дисциплина, что Ш1: правка владельца становится **новым** предложением с
  детерминированным id, «исполняется ровно то, что показали» (§7.10).
- **П4. `allowedCallers` ↔ `agentOnly`/`routineOnly`.** Границы вызова как поле декларации,
  проверяемое в рантайме, — у обоих; у A2UI это измерение добавлено к каталогу UI, у Orbis —
  к реестру тулов. Довод за то, чтобы у будущего каталога видов (И2) поле границ было с
  первого дня.

## Что не берём

- **Рантайм-протокол в чат** (surfaces, `updateComponents`-потоки): карточки выводятся из
  журнала и очереди решений, модель не рисует — см. вердикт А.
- **`@a2ui/react` зависимостью сейчас:** 1,04 МБ unpacked при дисциплине бандла (инициатива
  lazy-split), второй markdown-движок (`markdown-it` рядом с `react-markdown` и tiptap), темы
  CSS-переменными рядом с токенами Tailwind, и дрейф спеки: 0.8 → 0.9 был переписыванием,
  1.0 меняет снова, рендереры отстают на версию.
- **Агентную сторону:** SDK только Python, гайд для не-A2A потока — «TODO»; для Bun/TS это
  «напиши сам», то есть заимствовать нечего, кроме идей.
- **MCP-привязку сейчас:** нет свидетельств рендера A2UI хостами Anthropic; единственный
  MCP-клиент — локальный Claude Code (рулинг 23.08). Шов, не работа.

## Опровергаемые утверждения этого разбора

1. «Хосты Anthropic не рендерят `application/a2ui+json`» — по отсутствию упоминаний на
   `a2ui.org` и в посте Google; список хостов там не приведён.
2. «Агентного SDK для TypeScript нет» — по README и листингу `agent_sdks/` на 2026-09-09
   (только `python`); в сэмплах может лежать TS-код без пакета.
3. «Причина раздельности union'ов не названа» — по комментариям в `types.ts`; в леджерах или
   ревью фазы C причина могла быть записана.
4. Состав `@a2ui-sdk/react` (Radix + Tailwind) — по сниппету поиска, страница npm отдала 403.
