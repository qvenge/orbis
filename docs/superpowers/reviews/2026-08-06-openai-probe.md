# Проба OpenAI — принимает ли он схемы реестра Orbis

| Поле | Значение |
|---|---|
| Дата | 2026-08-06 |
| Повод | на счёте `ANTHROPIC_API_KEY` нет средств — путь модели мёртв целиком; PRD §7.7 называет мульти-провайдерность оставленным швом |
| Ветка | нет: проба сделана на `main` (`b87333a`) одноразовыми скриптами вне репозиторного кода |
| Ключ | OpenAI-ключ владельца, вписан в `apps/server/.env` (gitignored) |
| Модели | `gpt-5.5` (основная), `gpt-5.4-mini` (сравнение по цене) |
| Пакет | `@ai-sdk/openai@4.0.31` — та же мажорная линия, что установленный `@ai-sdk/anthropic@4.0.8` |

Проба отвечала на **два разных вопроса** и не смешивала их: (1) **приём схем** — берёт ли
OpenAI определения всех 19 тулов реестра, включая первый в истории реестра союз `anyOf`;
(2) **послушность** — ведёт ли себя модель на промпте v3, подогнанном под Claude.

---

## Итог одной строкой

**Приём схем — да, но только одним транспортом из двух.** Chat Completions принимает все
19 тулов; Responses API — тот, которым `@ai-sdk/openai` ходит **ПО УМОЛЧАНИЮ**, — отвергает
их при любой настройке строгости. Причина не в `anyOf`, а в lookahead-регекспе денежных
паттернов. Послушность `gpt-5.5` на промпте v3 хорошая, включая обе ветви союза и чипы D19.

---

## 1. Приём схем

### 1.1 Инвентаризация того, что уезжает модели

Собрана статически, без БД: реестр в `aspect_definitions` сидируется теми же
`aspectJsonSchema(meta.id)` и `meta.aiInstructions` (`scripts/seed-aspects.ts:16`), поэтому
статическая сборка `buildToolDefs` совпадает с тем, что читает исполнитель.

**19 тулов** (11 core + 8 `attach_<aspect>`). Конструкции JSON Schema, реально встречающиеся:

| Конструкция | Где |
|---|---|
| `anyOf` | **ровно один**: `attach_orbis_goal` → `properties.data.properties.progress_source.anyOf` (вложенно, не в корне; глубина схемы 10) |
| `format: uuid` | 11 тулов |
| `pattern` | 9 тулов (даты, timestamp, цвет, **три денежных**) |
| `enum` / `const` | 9 тулов |
| `minLength`/`maxLength`/`minItems` | 8 тулов |
| необязательные свойства | 9 тулов на верхнем уровне, ещё больше внутри `data` |
| `$ref`, `$defs`, `oneOf`, `allOf`, `not` | **не встречаются вовсе** (`$refStrategy: 'none'`) |

### 1.2 Результат по транспортам и строгости

Сырым `fetch` (без SDK), все 19 тулов:

| Транспорт | `strict` | Итог |
|---|---|---|
| `chat/completions` | false | **HTTP 200, принято** |
| `chat/completions` | true | HTTP 400 |
| `responses` | false | **HTTP 200, принято** |
| `responses` | true | HTTP 400 |

Через `@ai-sdk/openai` (тем путём, которым пойдёт реализация), те же 19 тулов:

| Способ | Итог |
|---|---|
| `provider(model)` — **транспорт по умолчанию, Responses API** | **ОТКАЗ** |
| `provider(model)` + `strictJsonSchema: false` | **ОТКАЗ** (тот же) |
| `provider.chat(model)` — Chat Completions | **ПРИНЯТО** |
| `provider.chat(model)` + `strictJsonSchema: true` | **ПРИНЯТО** |

Текст отказа Responses API — дословно:

```
Invalid JSON schema: regex lookaround is not supported.
Found at $.properties.data.properties.amount.pattern.
```

### 1.3 Что это значит на самом деле

**Виноват не `anyOf`.** Союз `progress_source` не всплыл ни в одной ошибке — ни в strict,
ни в loose, ни на одном транспорте. Опасение, ради которого проба и затевалась, не подтвердилось.

**Виноват `positiveDecimal`.** Паттерн `^(?!0+(\.0+)?$)\d+(\.\d+)?$`
(`packages/shared/src/schemas/aspects.ts`) содержит негативный lookahead — он и есть
«lookaround». Паттерн стоит у **двух** полей: `orbis/financial.amount` и
`orbis/goal.target_value`, то есть задевает **два тула из девятнадцати**.

> **Поправка 2026-08-06 (разведка опровергла контроллера).** Первая редакция этого отчёта
> писала «три поля, включая `orbis/budget.limit`». Неверно: `limit` объявлен через
> `nonNegativeDecimal` (`^\d+(\.\d+)?$`, `aspects.ts`) — lookahead там нет. Проверено
> прогоном по всем 19 тулам реестра (`.superpowers/probe/lookaround.ts`): попаданий ровно
> два, и Responses API в своём отказе называет только `$…properties.amount.pattern`.
> Вывод отчёта от поправки не меняется, но его величина меньше, чем звучала.

**Отказ Responses API безусловен.** `strictJsonSchema: false` его не снимает — валидация
регекспов на этом эндпоинте не зависит от строгости структурированного вывода. Это свойство
эндпоинта, а не настройки. Прямое следствие для реализации: **ходить только
`provider.chat(model)`**, и написать в коде, ПОЧЕМУ, — иначе первый же, кто «упростит» вызов
до `provider(model)`, получит отказ на трёх тулах из девятнадцати.

**Расхождение сырого `fetch` и SDK объяснимо и важно.** Сырым `fetch` Responses API отдал 200,
потому что проба явно передавала `strict: false` **и не проходила через трансформацию SDK**;
SDK же приводит схемы к своему виду и отправляет их так, что валидатор регекспов срабатывает.
Мораль общего свойства: **проба сырым транспортом не заменяет пробу тем путём, которым пойдёт
код.** Первый круг пробы дал бы ложное «всё хорошо».

### 1.4 Почему strict-режим не рассматривается

Потульная проба `strict: true` (по одному тулу, чтобы видеть адрес отказа): **6 из 19 проходят,
13 отвергнуты**. Ни один отказ не назвал `anyOf`. Причины ровно две, обе механические:

- `'required' is required to be … an array including every key in properties` — у нас есть
  необязательные поля (`entity_get.include`, `budget_status.month`, почти всё внутри `data`);
- `'additionalProperties' is required to be supplied` внутри вложенных объектов, порождённых
  `z.record` (`entity_create.aspects`, `batch_execute.operations[].input`).

Привести схемы к strict означало бы объявить обязательным всё необязательное — то есть
изменить схемы аспектов, а это **пересев реестра на проде** ради режима, который нам ничего
не даёт: вход тула всё равно валидирует ajv по реестру (стадия 2 исполнителя,
01-architecture §3). **Решение: strict не включаем.**

## 2. Послушность

Прогон полного tool-цикла по текстовому протоколу MVP (результаты тулов возвращаются
user-сообщением `[tool_result:<тул>] <JSON>`), исполнение подменено заглушками, промпт — **v3
без единой правки**, плюс инструкции активных аспектов, как их приклеивает `context.ts`.

### 2.1 `gpt-5.5` — четыре сценария

| Сценарий | Итог |
|---|---|
| Цель, ветка `sum` (`field` ОБЯЗАТЕЛЕН) | ✅ `progress_source: {query, aggregate:"sum", field:"amount"}` — ветка союза верная |
| Цель, ветка `count` (`field` ЗАПРЕЩЁН) | ✅ `field` не передан — дискриминация союза соблюдена |
| Чипы продолжений D19 | ✅ пришли **во всех четырёх** терминальных ходах, формат `[[suggest: … | … | …]]` точный |
| Маркер `[tool_result:…]` | ✅ понят, ответ строится по данным из него, дословно не цитируется |
| «Одна сущность на намерение» | ✅ одна сущность; сумма ушла в `meta`, а не в `orbis/financial` — **и это верно**: `category_ref` в схеме ОБЯЗАТЕЛЕН, категорий в заглушке нет, модель честно попросила пользователя классифицировать |

Опасение владельца — «промпт v3 подогнан на Claude, чипы могут перестать приходить» — **не
подтвердилось**: чипы пришли на первой же попытке и в каждом ходе.

### 2.2 `gpt-5.4-mini` — заметно хуже, в дефолт не годится

- вызвал `attach_orbis_goal` **дважды подряд** на одной сущности (у `gpt-5.5` — один раз);
- в сценарии «оплатить страховку» собрал `orbis/financial` **без `category_ref`** — ajv
  отверг бы это жёстким VALIDATION, то есть пользователь получил бы ошибку вместо задачи;
- в одном ходе из четырёх **не прислал чипы**.

**Вывод: дефолтная модель — полноразмерная.** Экономия на mini оплачивается отказами исполнителя.

### 2.3 Два дефекта, найденные пробой, — оба НЕ про OpenAI

**Д1. В шпаргалке грамматики промпта нет `tags=`.** Слово `tags` встречается в
`apps/server/src/llm/prompts/v3.ts` **ноль раз**, хотя фильтр существует
(`packages/shared/src/query/grammar.ts:66`) и является естественным способом выразить
«доходы с тегом savings». Следствие наблюдалось живьём: модель сочиняет ключ `tag=`
(единственное число), а он грамматикой отвергается. Проверено прогоном настоящего `parseQuery`
на том, что сочинила модель:

```
OK     aspect=orbis/financial, direction=income, tags=savings
ОТКАЗ  aspect=orbis/note, tag=book        → {"message":"неизвестное поле 'tag'","position":19}
OK     aspect=orbis/note, tags=book
```

Цена: цель создаётся успешно, а её прогресс молча приезжает `unsupported` — потому что
`progress_source.query` не разбирается. Пользователь видит цель без полосы и без объяснения,
что запрос кривой. **Дефект провайдеро-независимый**: на Claude он ровно такой же, просто
проверить это сейчас нечем.

**Д2. Лишний `attach_*` после `entity_create`, который уже нёс аспект.** `gpt-5.5` в обоих
целевых сценариях сначала создал сущность с `aspects: {'orbis/goal': …}`, а следом вызвал
`attach_orbis_goal` с теми же данными. Промпт просит навешивать аспекты сразу одним
`entity_create` — модель это делает и всё равно дублирует вызов. Стоимость: лишний шаг цикла
и лишняя запись аудита. `gpt-5.4-mini` дублирует трижды.

## 3. Что проба НЕ проверила

- **Anthropic после правок.** Сравнить поведение двух провайдеров на одном промпте нечем:
  на счёте Anthropic нет средств. Всё, что ниже написано про «провайдеро-независимость»,
  доказано чтением кода и пробой на OpenAI, но не сравнительным прогоном.
- **Приложение целиком.** Проба ходила мимо `send-message.ts`: не проверены метеринг,
  entitlements, персистенция ленты, карточки, `extractSuggestions`. Это работа живого смоука.
- **Долгие цепочки и лимит шагов.** Циклы сходились за 3–5 шагов при `MAX_AGENT_STEPS`;
  поведение у самого потолка не проверялось.
- **Стоимость.** Токены за прогон снимались (`in≈5090` на ход с полным реестром тулов),
  но месячная стоимость не оценивалась.

## 4. Что из этого следует для реализации

1. **`provider.chat(model)`, не `provider(model)`** — с комментарием, называющим отказ дословно.
2. **strict не включать** — вход валидирует ajv по реестру.
3. **Дефолтная модель — полноразмерная** (`gpt-5.5` на дату пробы), не mini.
4. **`DEFAULT_ANTHROPIC_MODEL` в метеринге — дефект второго провайдера.**
   `apps/server/src/ai/send-message.ts:91` берёт имя модели как
   `env.ORBIS_LLM_MODEL || DEFAULT_ANTHROPIC_MODEL`: при OpenAI без явной
   `ORBIS_LLM_MODEL` метеринг записал бы `claude-sonnet-5`. Имя модели обязано приходить
   от самого провайдера, а не от дефолта чужого.
5. **Д1 (`tags=` в шпаргалке грамматики) чинить** — он делает цели молча нерабочими,
   и найден ровно в той области, которую эта работа и трогает.

## 5. Воспроизведение

Скрипты пробы лежат в `.superpowers/probe/` (директория не коммитится):
`dump-tools.ts` (инвентаризация), `openai-probe.ts` (приём схем + первый круг послушности),
`openai-cycle.ts` (полный tool-цикл), `sdk-path.ts` (путь через SDK), `sdk-matrix.ts`
(матрица транспорт × строгость), `pq.ts` (разбор сочинённых моделью запросов настоящей
грамматикой). Запуск: `set -a && . ./apps/server/.env && set +a && bun .superpowers/probe/<файл>.ts [модель]`.
