## Что это

**T3 Code** (`t3.codes`, `github.com/pingdotgg/t3code`, MIT) — «The open-source control plane
for coding agents», в README — «agent harness control surface». Делает T3 Tools Inc (Theo
Browne, t3.gg / T3 Chat; второй принципал — Julius). Репозиторий открыт 08.02.2026.

| Факт | Значение |
|---|---|
| Звёзды / форки | 22.1k / 5.5k (GitHub, 09.09.2026); лендинг: «21,000+ stars», «Tolerated by over 200,000 devs» |
| Версия | v0.0.40 от 08.09.2026; nightly по нескольку в день; открытых issue > 1 700 (август) |
| Зрелость | «Very very early in this project. Expect bugs.»; «We are (mostly) not accepting contributions yet» |
| Агенты | Claude Code, Codex, Cursor, Grok Build, OpenCode, Google Antigravity — **на подписках пользователя**: «No keys resold. No quota caps.» |
| Поверхности | Electron (macOS/Windows/Linux), iOS, Android, web `app.t3.codes`, `npx t3@latest`, headless `npx t3 serve`, фоновый сервис (systemd / launchd) |
| Ниша | та же, что bb / Orca (раунд 4), Superset, Conductor: оболочка над чужими агентами |

**Три части.** Сервер («environment») «owns providers, execution, files, and durable state» и
живёт на машине с кодом; клиенты — «views onto that server. A client holds no repository and
runs no agent»; транспорт — loopback, LAN, Tailscale, SSH или хостовый relay T3 Connect. Модель
сам T3 не вызывает никогда: «it never talks to Claude» (обзор continuumcode) — вся сила у
агента, T3 только окно перед ним.

**Единица работы — тред.** «A thread is the unit of work, and a thread can own a git worktree, a
branch, a diff, and a pull request». На тред — переключатель «свой worktree / локальный
checkout». Дифф по ходам (turn diff), чекпойнты «stored as a hidden Git ref», кнопка
«Commit, Push, & Create PR» с генерируемыми заголовком и телом; draft / stacked / amend.
Состояния треда: Active / Pinned / Settled / Snoozed; сервер сам находит PR для незакрытых
тредов, и «the linked pull request participates in automatic settlement».

**Права — режимом на тред.** Четыре режима: Supervised («Requests approval for commands and
file changes»), Auto-accept edits, Auto («Uses the provider's automatic review»), Full access.
**По умолчанию — Full access**; дочерний тред «inherits its mode». «Interaction mode» (plan /
chat) отделён от политики прав.

**Внутри — event sourcing.** «The event log is the source of truth for orchestration state»:
команда → чистый decider → события → проекции; «Events, persisted projections, and the accepted
command receipt commit in one database transaction»; «Reactors perform side effects after intent
has been recorded, then feed results back through commands». Провайдеры — за адаптером:
«Capabilities must describe what the provider can actually do» (Antigravity умеет чекпойнт, но
не откат беседы — revert отклоняется до правки файлов). Маршрутизация по экземпляру, не по
драйверу: «two accounts using the same driver do not share mutable session or catalog state».

**Слабости, которые называют обзоры:** «The diff is hard for me to read», «UX isn't smooth yet.
Small things (focus, scroll, cursor behavior) add up», падения на KDE Plasma 6, пять
провайдеров = «five installs, five logins, and five sets of auth failure modes», нет команд /
SSO / биллинга («there is no account model beyond the one that authenticates the tunnel»),
фонового сервиса нет на Windows, хост «must stay running and reachable while you work».

## Что видно на фоне раунда 4

1. **Пятая подряд оболочка с теми же четырьмя признаками** (чужие агенты на подписке, открытая,
   локально-первая, живёт внутри репозитория). Выводы раунда 4 держатся без правок; мобильная
   поверхность — теперь **5/5**. Подтверждение курса ADE-среза 1 (грант + скоуп + глаголы,
   исполнитель снаружи), не новость.
2. **Push, не pull.** Пользователь брифует тред; агент никогда не приходит за работой сам.
   Наблюдение «pull-модели нет ни у кого» (раунд 1, ревалидация) держится. При этом в релизах —
   «relay notification policy sharing and waiting agent prioritization»: телефонная поверхность
   у них — ровно «увидел — ответил» для кода (пуш, когда агент ждёт). V3 подтверждён ещё раз.
3. **Дефолт «Full access» — рыночный сигнал по сфере кода.** Разработчики принимают автономию
   агента над кодом по умолчанию; у нас в ADE-срезе 1 автономный флаг тикета «по умолчанию
   выключен». Противоречия нет — D38 («предлагает, а не действует») писан для сфер жизни, — но
   при планировании ADE-среза 5 стоит помнить, что для `orbis/repo` рынок держит обратный дефолт.
4. **Участника-сущности нет** — только туннель. В7 и гранты §4.14 остаются нашим отличием.
5. **Стратегически — не конкурент.** Ни графа, ни памяти, ни рутин, ни жизни; конкурент Orca /
   bb / Superset / Conductor. Значимость для нас другая: T3 задаёт **ожидания разработчика от
   сферы кода** — «тред ↔ ветка ↔ дифф ↔ PR одной кнопкой». Перестраивать это внутри Orbis не
   нужно; правильный стык — тикет Orbis ↔ тред T3-подобной оболочки через ссылку на PR (И3).

## Идеи к перенятию

### И1. Среда исполнителя — сущность с устойчивой идентичностью; Orbis — брокер, не прокси

**Прецедент.** `docs/internals/remote.md`, `environment-auth.md`, `t3-connect.md`:
«Each connection joins a client to one environment» с идентичностью, независимой от рестартов
и адресов; «Advertised endpoints are reachability hints… only the connecting device can prove
that a route works»; «Authentication remains the environment's responsibility for every route»;
«A relay token is never an environment login»; «Exchanging a bootstrap credential can narrow
that grant but cannot widen it»; relay «does not proxy their HTTP or WebSocket sessions… The
relay never receives that session token» (одноразовый bootstrap, привязанный к DPoP-ключу
клиента); «Endpoint selection must not silently fall back to loopback»; SSH-очистка «stops a
remote server only if the launcher owns it».

**Почему нам.** Шов 7 ADE («удалённый запуск исполнителя по SSH»; после ревалидации — «среда
исполнителя описывается декларацией при задаче… SSH — первый транспорт») описывает, *что*
поднимать, но не инварианты облачной стороны. У нас граф в облаке, код и учётки провайдеров —
на машине владельца, исполнитель тянет очередь по MCP. T3 — готовый список того, чем облако
**не имеет права** становиться, когда дотягивается до машины: не прокси трафика, не держатель
сессии машины, не источник её прав (bootstrap только сужает). Второе: идентичность среды ≠ её
адрес — машина как участник (В7) с устойчивым id, к которому крепится грант, а не к endpoint'у.

**Цена.** В Б-1 — ничего. Ограничение дизайна для ADE-среза 5; дёшево записать сейчас, дорого
переделывать, если Orbis однажды окажется прокси между телефоном и машиной с кодом.

**Адрес-кандидат.** ADE-спека, «Швы под будущее», дополнение к п. 7; видение В7 (машина —
участник-сущность). Полный event-log relay и Clerk-идентичность не берутся — облако у нас уже
есть.

### И2. Намерение записано до внешнего эффекта; «завершился» ≠ «улёгся»

**Прецедент.** `docs/internals/overview.md`, `glossary.md`: «the decider produces events without
performing provider or filesystem work»; «Reactors perform side effects after intent has been
recorded, then feed results back through commands»; команда — «Accepting it does not mean its
side effects have finished»; «Command receipt — a durable record of a command's result, used to
make retries idempotent»; **Quiesced** — «The relevant follow-up workers have finished, beyond
the provider turn merely ending»; ход — «Provider work can finish before checkpoint and diff
work settles».

**Почему нам.** Журнал §7.8 пишется постфактум, и для мутаций графа это верно: мутация и запись
коммитятся одной транзакцией. Но всё, что **покидает граф**, — доставка результата рутины в
канал (ревалидация IV.2 п. 16), пуш V3, вебхуки, git-операции внутреннего исполнителя в срезе 5 —
постфактумной записью врёт: процесс упал между эффектом и записью → журнал не знает об
эффекте, повтор делает его дважды. Порядок T3: намерение с ключом дедупликации → эффект →
результат возвращается командой. Половина у нас есть: дедуп-ключи `defer:{runId}:{hash}` (D42),
receipts по client-UUID / `batch_id` (§7.8), флаг `external` у шага прогона. Нет двух вещей:
**правила порядка** для наружных эффектов и **второго терминального состояния** прогона —
«завершился» (исполнитель сказал) против «улёгся» (все хвосты доставлены). Без второго экран
показывает «готово» раньше, чем уведомление ушло, а ретрай после падения не отличим от дубля.

**Цена.** Правило для будущих механизмов, в Б-1 ничего. **Полный event sourcing не берётся**:
состояние-первое хранение + append-only журнал остаются; ES — инфраструктура наперёд, тот же
довод, что отклонил bi-temporal (D11).

**Адрес-кандидат.** PRD §7.8 — правило «намерение до внешнего эффекта» (outbox); спека V3 при
написании; ADE-срез 5 (`external`-шаги).

### И3. Тикет закрывается внешним сигналом, а не кликом

**Прецедент.** `docs/user/thread-sidebar.md`: «The server automatically finds pull requests for
unsettled threads»; «The linked pull request participates in automatic settlement»; состояния
Active / Pinned / Settled / Snoozed, «Settling a thread removes its pin».

**Почему нам.** Статусы тикета `inbox | planned | in_progress | waiting | done | cancelled`;
`done` ставит `orbis_finish` — то есть исполнитель, когда *он* закончил. Для сферы кода настоящее
«готово» — PR смержен, и это случается позже, снаружи и не всегда (PR могут закрыть без мержа).
Рутина-наблюдатель за состоянием PR, запускаемая изменением данных (триггер от Notion Custom
Agents, ревалидация III.2), закрывает тикет сама и возвращает в `waiting` с запиской при закрытии
без мержа. Это прямое следствие анти-цели 5 («не ещё один трекер»): владелец не закрывает
тикеты руками. Snooze — второстепенно: «спрятать до даты» у нас покрывается расписанием и
`prefer/overdue`, отдельного примитива не нужно.

**Цена.** Ссылка на PR в `orbis/repo` (сейчас код мержится «через PR», но тикет PR не знает),
триггер «от изменения данных» — не построен (IV.2), рутина — V1 есть. Средняя.

**Адрес-кандидат.** ADE-спека, «Швы под будущее», новый п. 8; рутины V2 (триггер от данных).

### И4. Ответы с телефона переживают отсутствие сети — очередь на исходе, не только на входе

**Прецедент.** `docs/user/composer.md`, `docs/internals/connection-runtime.md`: на мобильном
«queue messages while disconnected… Uploads resume when you reconnect. Drafts and queued
messages survive app restarts»; «Reconnection does not automatically replay mutations, whose
retry and idempotency rules belong to the operation»; «Cached projections remain readable
offline» и не должны «suggest a live connection» или перетирать новые данные при
переподключении.

**Почему нам.** Офлайн у нас — «буфер на входе» (§5.3): только create fast-path, правки и
LLM-путь — нет, и это осознанно («не тихая деградация и не очередь»). Но V3 «увидел — ответил»
об это ломается: ответ на чекпойнт или на пачку решений D42 из тоннеля метро — мутация
существующего pending, сегодня не буферизуется. Это самая безопасная мутация для буфера: у D42
уже есть дедуп-ключи и правило «первая записанная судьба финальна» со структурным
`{status:'stale'}` — опоздавший ответ из очереди отклоняется честно, дубля нет. Правило T3
«ретрай и идемпотентность принадлежат операции, а не переподключению» дословно совпадает с
§5.3 («идемпотентность обязательна и онлайн»).

**Цена.** Расширить retry-буфер на `approvePending` / `rejectPending` / ответ на вопрос; кэш не
должен рисовать ответ как доставленный. Малая; кладётся в V3 естественно.

**Адрес-кандидат.** Спека V3 (карта видения, п. 5); PRD §5.3 — оговорка «буфер на исходе для
решений».

### И5. Цитата несёт выдержку и источник в самом тексте; при неоднозначности — не угадывать

**Прецедент.** `docs/internals/assistant-citations.md`: цитаты «embed selected excerpts and
source identity directly in message text, persisting across drafts, clipboard copies, and sent
messages without requiring a separate citation store»; селектор требует «an unambiguous context
match, even if one occurrence still sits at the saved offsets»; «guessing could highlight the
wrong claim» — неоднозначное остаётся неразрешённым; при изменении источника «the saved quote
remains usable».

**Почему нам.** Шов 3 ADE («предложение обязано ссылаться на прогон-триггер») и bootstrap памяти
(«AI предлагает сохранить факт из разговора») фиксируют *ссылку*; T3 показывает форму: выдержка
+ идентичность источника едут **в самом тексте**, переживают копирование в другой тред и
остаются читаемыми, когда источник ушёл. Дисциплина «якорь разошёлся → отказ, не догадка» — та
же, что у Р2 и hashline omp (раунд 1); здесь она применена к цитатам, не к правкам.

**Цена.** Малая: формат карточки предложения и `orbis/memory`-факта. **Адрес-кандидат.** ADE
шов 3 — уточнение; ревалидация IV.2 п. 12 (bootstrap памяти).

### Подтверждения (нового не дают, записаны, чтобы не искать заново)

- **«Capabilities must describe what the provider can actually do»**, отказ **до** правки файлов —
  наша дисциплина 21 отказа / `MODULE_DISABLED` / `disabled_modules` (ревизия 3). Дополнение из
  T3: способности объявляются на **экземпляр** провайдера, не на его тип.
- **Copy-on-write настроек**: «Shared actions apply to inheriting projects; editing a project's
  actions creates an independent list» — то же, что `registry_deltas` над system-реестром.
- **Режимы прав на тред** — грубее В4 (классификатор по классу действия) и D42; берём только
  два инварианта, которые у нас и так держатся: дочерняя работа наследует политику родителя;
  разовое одобрение (`once`) политику не расширяет — расширяет только правило памяти (§7.8
  «эскалация в правило»).
- **Стоимость — реконструкцией из локальной истории сессий** («estimated API-equivalent cost», не
  счёт подписки), прайс моделей — данные с сохранением «last usable manifest». Для «сколько стоил
  тикет» (С5 ADE) Orbis вызовов внешнего агента не видит — стоимость должна приходить от
  исполнителя в `orbis_finish`; проверить при срезе 5, есть ли поле.

## Что сознательно не берём

- **Electron и нативные iOS/Android.** Orbis — PWA; «увидел — ответил» строится на пуше в PWA с
  push-leases (Buzz, ревалидация Н4).
- **Оболочку над чужими CLI и переключение провайдера в UI.** Круг исполнителя (D37) оставляет
  код и работу с ним у агента; Orbis кода не держит и не должен.
- **Режим прав на тред с дефолтом Full access.** Ручка «весь тред без спроса» позволила бы
  рутине «уйти в полный доступ» одним переключателем — против анти-цели 3 («не чёрный ящик»).
  Классификатор по действию + отложенная пачка D42 — продукт, а не ограничение.
- **Полный event sourcing** (decider / projector / reactor как каркас) — см. И2: берём порядок
  «намерение → эффект» для наружных эффектов, не архитектуру.
- **Импорт cookies из браузеров** («Import browser sessions») — вне скоупа и чувствительно.
- **SnapShot окна другого приложения с деревом accessibility** — из PWA недостижимо; для
  захвата у нас share-sheet и quick capture.
- **Хостовый relay с Clerk-идентичностью** — облако у нас уже есть; берутся инварианты (И1).
