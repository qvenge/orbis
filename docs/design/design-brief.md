## 1. Продукт в двух абзацах

**Orbis — персональная AI-операционная система для жизни.** Не очередной трекер задач или расходов, а одно место, где живёт всё, что человек хочет помнить, планировать и считать, — и AI, который умеет с этим работать. Продукт продаёт не трекинг, а **связность**: ответы на вопросы, требующие данных из нескольких доменов сразу. «Могу ли я позволить себе кроссовки?» — ответ требует остатка в конверте бюджета, предстоящих recurring-платежей и уже запланированных покупок. Orbis знает всё сразу, потому что всё это — один граф.

Ментальная модель — операционная система:

| Orbis | Аналог в ОС |
|---|---|
| Граф сущностей | Файловая система |
| Чат (AI + fast-path) | Терминал |
| Entity Browser | Файловый менеджер |
| Views (Budget, Agenda, будущие) | Приложения |

Два якорных сценария: **личная ОС** (задачи, финансы, заметки, планирование с AI) и **рабочее пространство человек + агенты** — внешние AI-агенты (Claude Code через MCP) работают в том же графе; их действия видимы, атрибутированы («🤖 агент: закрыл задачу X»), обратимы и управляемы с телефона.

## 2. Пользователь и контекст использования

Сейчас — один требовательный пользователь (владелец продукта): пользуется **с телефона и с ноутбука**, ежедневно, PWA. Второй «пользователь» — AI-агенты, но у них нет UI: их работа видна человеку через чат и списки. Задел на публичность заложен в архитектуре, но дизайн оптимизируется под ежедневное личное использование, не под лендинг.

Ключевые метрики, на которые влияет дизайн:
- median time-to-log расхода **< 5 сек** (fast-path < 2 сек) — ввод не должен иметь трения;
- доля AI-записей, потребовавших исправления, < 10% — исправление должно быть «в одно касание», иначе доверие падает;
- ежедневное использование 30+ дней подряд — привычка складывается из скорости и предсказуемости.

## 3. Ключевые доменные понятия (глоссарий для дизайнера)

- **Сущность (entity)** — универсальная единица: задача, расход, заметка, категория, конверт. Имеет title, emoji, теги, body (markdown), аспекты. Сущность **может иметь несколько аспектов сразу**: «Купить кроссовки 8000₽ к субботе» — одна сущность task + financial + schedule, видна в задачах, бюджете и агенде без дублирования.
- **Аспект (aspect)** — типизированная грань сущности. Восемь встроенных:
  - `orbis/task` — статус (inbox / planned / in_progress / waiting / done / cancelled), приоритет (low/medium/high), срок, «кого ждём»;
  - `orbis/financial` — сумма, направление (income/expense), категория, дата, planned/факт, recurring;
  - `orbis/schedule` — start_at/end_at, «весь день», правило повторения (recurrence), место;
  - `orbis/note` — маркер «это заметка»;
  - `orbis/budget` — конверт: категория, лимит, период, carryover;
  - `orbis/category` — иконка, цвет, синонимы для распознавания ввода, класс расходов (fixed/discretionary);
  - `orbis/memory` — память AI: факт («не ем свинину») или правило («бар → Развлечения»);
  - `orbis/goal` — цель: целевое значение, единица и источник прогресса (запрос по графу + агрегат). Прогресс считает сервер и рисует полосой **на detail-экране**; в строках списков полосы нет (04-decision-log D23).
- **View** — линза поверх графа (Budget, Agenda). Данные существуют до views: удалил view — ничего не потерял.
- **Конверт** — лимит трат по категории на период; «потрачено» всегда вычисляется из реальных транзакций.
- **Fast-path** — мгновенный детерминированный парсер частотного ввода («обед 340»): офлайн, без LLM, карточка появляется быстрее, чем открылась бы форма.
- **Тред** — персистентный диалог с AI: один глобальный + по одному у каждой сущности («обсуждение живёт рядом с вещью»).
- **Smart list** — сущность с живыми query-блоками в body (Daily Planning, Upcoming, All Tasks, «Год», «Жизнь»), закрепляется в сайдбаре — кроме «Жизни», её находят в Browser по тегу.
- **Retry-буфер** — очередь fast-path-записей, ожидающих сеть; ввод не теряется без соединения.

## 4. Принципы, которые дизайн обязан сохранить

1. **Ввод без формы, пользователь не выбирает режим.** Он просто пишет; система сама решает: уверенный паттерн — мгновенный fast-path, остальное молча уходит в LLM. Никаких переключателей «умный/быстрый режим».
2. **Каждое действие AI обратимо и правится в одно касание.** Inline-правка полей прямо в карточке чата; Undo везде; после Undo карточка визуально «гаснет». Система учится на повторных исправлениях (предлагает запомнить правило).
3. **Никаких push и проактивных сообщений.** Orbis не пишет первым. Вся сигнализация пассивная: бейджи на вкладках, секция «Просроченное» сверху Agenda, подсветка перерасхода в Budget.
4. **Views — обычные экраны, не модалки.** Budget — такой же полноправный экран, как Chat.
5. **«Назад» всегда возвращает туда, откуда пришёл.** Предсказуемый push-стек в каждой вкладке.
6. **Работа агентов прозрачна.** Действия внешних агентов выглядят как системные сообщения с обычными карточками и Undo — не спрятаны в лог.
7. **Данные принадлежат пользователю.** Экспорт всего графа одной кнопкой; память AI видима и редактируема как обычные сущности.

## 5. Информационная архитектура

### 5.1 Навигация

Четыре вкладки нижней панели (на десктопе — сайдбар): **Chat / Browser / Agenda / Budget**. Поверх каждой — собственный стек push-экранов:

```
нижняя панель:   [ Chat ]        [ Browser ]        [ Agenda ]         [ Budget ]
корень:          глобальный      список сущностей   список дней        Overview
                 тред            + сайдбар pinned   (сегодня → +7)     (конверты)
push-стек:       detail → detail → … (внутри своей вкладки)
```

- Каждая вкладка хранит **свой** стек; переключение вкладок стеки не сбрасывает.
- Повторный тап по активной вкладке сворачивает стек до корня.
- Detail-экран сущности — **единый для всех вкладок**: тап по сущности в любом списке пушит его.
- Состояние (активная вкладка + стеки) восстанавливается после перезапуска.
- ⚙ настройки — иконка в хедере корневого экрана каждой вкладки.
- Эволюция заложена: при 3+ установленных views вкладка Budget станет «Views» со списком.

### 5.2 Бейджи вкладок (пассивная сигнализация)

| Вкладка | Бейдж |
|---|---|
| Chat | Размер retry-буфера (записи, ждущие сеть); пуст — бейджа нет |
| Browser | Без бейджа |
| Agenda | Число просроченных элементов |
| Budget | Число конвертов в зоне тревоги/перерасхода (> 85% лимита) |

## 6. Экраны и флоу

### 6.1 Chat (главный экран)

Мессенджер-UI: бесконечный диалог с AI, поле ввода внизу, история скроллом вверх. Пока AI отвечает — typing-индикатор, поле остаётся активным (сообщения встают в очередь). Ответ приходит целиком (стриминг — future).

```
┌──────────────────────────────────────────┐
│  …история (скролл вверх)…                │
│              обед 340  ◄── пользователь  │
│  ┌────────────────────────────────────┐  │
│  │ ⚡ без AI                          │  │
│  │ 🍔 Обед — 340 ₽ → Еда             │  │
│  │ [категория ▾] [сумма] [Undo]      │  │
│  │ не то? → разобрать с AI           │  │
│  └────────────────────────────────────┘  │
│ ┌──────────────────────────────────────┐ │
│ │ ⏳ ждут отправки: 2                  │ │  ← retry-буфер
│ └──────────────────────────────────────┘ │
│  [ поле ввода…                    ➤ ]    │
└──────────────────────────────────────────┘
```

**Типы карточек в ленте:**

| Тип | Когда | Содержимое |
|---|---|---|
| `entity_card` | Сущность создана/обновлена (AI, fast-path или агент) | title + иконки аспектов + ключевые поля (сумма+категория / статус+срок); inline-правка полей; Undo; тап по заголовку → detail |
| `entity_list` | Ответ-перечисление («покажи задачи на неделю») | заголовок + список строк в native-рендеринге |
| `query_result` | Ответ-агрегация | число + подпись («Еда в июне: 12 430 ₽ из 30 000 ₽») + «показать список» |
| `import_review` | CSV-импорт выписки | таблица ревью (см. 6.5) |
| `confirmation_card` | Рискованное действие требует подтверждения | превью действия + [Подтвердить] / [Отменить] |
| `error_card` | Действие не удалось | что и почему + следующий шаг |

**Fast-path-состояния карточки:** «⚡ без AI» (мгновенно), «⏳ ждёт отправки» (офлайн, в буфере), «отменено» (после Undo — погашена, поля заблокированы). Рядом с fast-path-карточкой — действие «не то? → разобрать с AI».

**Retry-буфер в UI:** индикатор «ждут отправки: N» над полем ввода; тап → список ожидающих, каждую можно отменить до отправки. **Списка сегодня нет** — тап по индикатору досылает буфер вручную (кнопка «Ждут отправки: N. Отправить сейчас»), то есть жест под список занят: обещание остаётся в силе, но вернуть его придётся другим аффордансом (04-decision-log D32). Без сети LLM-путь честно недоступен: поле ввода объясняет «нет сети — доступен только быстрый ввод».

**Тред сущности** — тот же чат-компонент с контекст-якорем, вкладка «Тред» на detail-экране. Для задач, которые ведёт внешний агент, тред — рабочее место совместной работы: агент пишет заметки о ходе, владелец отвечает с телефона.

### 6.2 Entity Browser

```
┌─────────────┬────────────────────────────────────┐
│ САЙДБАР     │  [ поиск… ]  [ фильтры ▾ ]         │
│ 📌 Pinned   │  ◉ Закончить API   ‹high› 13.06   │
│ ☀️ Daily…(4)│  ◯ Купить кроссовки 👟  сб        │
│ 🗓 Upcoming…│  🔒 Задеплоить       ‹ждёт API›    │
│ 📋 All Tasks│  📄 Идея про отпуск               │
│ (drag ⇅)    ├────────────────────────────────────┤
│             │  [ + быстрая запись…           ➤ ] │  ← quick-capture
└─────────────┴────────────────────────────────────┘
```

- Сайдбар: pinned-сущности с drag-перестановкой и бейджами-счётчиками (у Daily Planning — размер Inbox). На узких экранах — выдвижная панель.
- Список: все сущности, сортировка `updated_at:desc`, infinite scroll по 50, поиск + панель фильтров (теги, аспекты, статус, приоритет, даты). Кнопка «Сохранить как smart list».
- Quick-capture бар внизу: создаёт сущность из текста **без интерпретации** (текст → title). Контекстен: на корне — заметка; на smart list — задача в inbox; на другой сущности — её ребёнок.

**Native-рендеринг строк** (един для Browser, query-виджетов, карточек чата, Agenda):
- задача: чекбокс с цветом по приоритету (high — красный, medium — жёлтый, low — серый), статус-бейдж (inbox/waiting/cancelled), 🔒 у заблокированных, счётчик детей «2/5», срок (просрочен — красным);
- время: `start_at` (диапазон/«весь день»), 🔁 у recurring-шаблонов;
- финансы: сумма со знаком и цветом (расход `−340 ₽` красным, доход `+150 000 ₽` зелёным) + бейдж категории;
- мульти-аспектная сущность комбинирует: «Купить кроссовки» = чекбокс + сумма + день недели;
- сущность без аспектов — просто title + теги.

### 6.3 Detail-экран сущности (единый)

```
┌────────────────────────────────────────────┐
│ ←   👟 Купить кроссовки               ⋮    │
│ [ Сущность ]  [ Тред ]                     │
│  #task  #expense  #running                 │
│ ────────────────────────────────────────── │
│  body: markdown, [[entity:…]]-ссылки,      │
│  {{query:…}}-блоки как живые виджеты       │
│ ────────────────────────────────────────── │
│  Аспекты:  [Task ▾] [Financial ▾] [+аспект]│
│  Подзадачи (2/5):  ◉ … ◯ … [+ подзадача]  │
│  Блокировки · Связанное (backlinks)        │
├────────────────────────────────────────────┤
│  [ + быстрая запись…                  ➤ ]  │
└────────────────────────────────────────────┘
```

Секции сверху вниз (пустые скрываются): title+emoji (правка на месте) → теги чипами → body (markdown-редактор; query-блоки рендерятся живыми виджетами со списками; невалидный блок — красная плашка с ошибкой, никогда не пустой список) → карточки аспектов (поля по схеме, inline-правка, «снять аспект», «+аспект») → подзадачи чеклистом → блокировки → backlinks. Вторая вкладка — «Тред». Меню ⋮: закрепить / архивировать / скопировать ссылку.

### 6.4 Agenda (список дней)

```
┌──────────────────────────────────────────┐
│  ⚠ Просроченное (2)            ← красный │
│   ◉ Закончить API        срок был 11.06  │
│ ──────────────────────────────────────── │
│  Сегодня · сб, 13 июня                   │
│   весь день   Отпуск: день 1     ✈️      │
│   09:00   Стендап                📅 🔁   │
│ ──────────────────────────────────────── │
│  Вс, 14 июня  — день свободен —          │
└──────────────────────────────────────────┘
```

Горизонт «сегодня → +7 дней», секции по дням. «Просроченное» всегда сверху с красным акцентом. Пустой день не скрывается («день свободен») — горизонт читается целиком. Это сознательно список, не календарная сетка (полный Calendar — future).

### 6.5 Budget

**Overview (корень вкладки):** заголовок периода с переключателем `[◀ месяц ▶]`; карточка баланса (доход − расход, цвет по знаку); **сетка карточек-конвертов**; секции Coming up (recurring на 14 дней), Planned (запланированные покупки), Unbudgeted (траты без конверта).

Карточка конверта: иконка+имя категории, **прогресс-бар** `spent / effective_limit` с порогами подсветки — **< 60%** цвет категории, **60–85%** жёлтый (внимание), **85–100%** оранжевый ⚠ (тревога), **≥ 100%** красный 🔴 (перерасход); под баром — остаток и темп «~600 ₽/день» (при перерасходе «—/день»); carryover-бейдж «↩ +1 200» при переносе остатка. Будущий период — пустой нейтральный бар и «начнётся DD.MM»; закрытый — итог, приглушённая карточка, «завершён».

```
│  🍔 Еда                 🚕 Транспорт          │
│  ███████░░░ 72%         █████████▓ 91% ⚠      │
│  ост. 8 400 ₽           ост. 900 ₽            │
│  ~600 ₽/день            ~64 ₽/день            │
│  ↩ +1 200 (перенос)                           │
```

**Экран категории:** карточка текущего конверта → «Правила» (текст из body категории) → мини-тренд 3–6 месяцев (столбики spent по месяцам со штриховой линией лимита) → список транзакций месяца → «+ запись в эту категорию». Кнопка [Тред] в хедере.

**Экран «Транзакции»:** полный список с финансовыми фильтрами (категория, направление, период, диапазон сумм, planned) и поиском. Строка: дата, title, 🔁 у recurring, сумма ± цветом, бейдж категории справа. Свайпы: влево — рекатегоризация, вправо — пометить recurring.

**Импорт CSV:** выбор файла → AI распознаёт структуру → экран ревью со статусами строк (✓ новая с редактируемой категорией / ⊘ вероятный дубль / ⟳ уже импортирована) и сводкой «✓ новых 38 · ⊘ дубли 6 · ⟳ уже 3» → массовое подтверждение одной кнопкой → итог-карточка.

**Rollover (новый месяц):** таблица по категориям — факт прошлого месяца, carryover, предложенный AI лимит (редактируемый); [Обнулить переносы], [Создать N конвертов]. Триггер — первое открытие Budget в новом месяце.

**Quick-add бар:** числовая клавиатура суммы, пилюли 4–5 последних категорий, опциональный title, переключатель расход/доход, [Записать].

### 6.6 Настройки

Разделы: Общие (таймзона, валюта, начало недели) · Память AI (Browser с фильтром по memory-сущностям + поясняющий текст) · Аспекты (список реестра) · Views · Экспорт данных (JSON-дамп одной кнопкой).

### 6.7 Онбординг

Автосидирование без мастера настройки: 12 стартовых категорий с иконками и синонимами (Еда 🍔, Транспорт 🚕, Жильё 🏠, Здоровье 💊, Подписки 🔁, Развлечения 🎉, Одежда 👕, Образование 📚, Путешествия ✈️, Подарки 🎁, Зарплата 💰, Фриланс 💻), пять smart lists (Daily Planning ☀️, Upcoming 🗓️, All Tasks 📋, «Год» 🎯, «Жизнь» 🧭), из которых в сайдбаре закрепляются четыре — «Жизнь» открывают раз в год и находят в Browser по тегу, — глобальный тред.

## 7. Характерные edge-состояния, требующие дизайна

- Пустые состояния: тред до первого сообщения; «ничего не найдено» у валидного запроса; «день свободен» в Agenda; первый месяц Budget без истории (AI спрашивает доход и оценки вместо предложения).
- Ошибочные: красная плашка невалидного query-блока с указанием места; error_card с причиной и следующим шагом; конфликт конкурентной правки body («перезагрузить и повторить»); путь циклической блокировки «A → B → C → A».
- Офлайн: карточки «⏳ ждёт отправки», список буфера, объяснение в поле ввода.
- Подтверждения: завершение родителя с активными детьми (три варианта, без молчаливого каскада); confirmation_card для рискованных действий агента; «покупка совершена?» при закрытии задачи-покупки (перевод плана в факт).
- AI недоступен (сбой провайдера/лимит): явная ошибка с «повторить», всё остальное работает.

## 8. Текущая дизайн-система (из кода `apps/web`)

Действующий визуальный язык — **«тихая бумага + чернила»**: почти монохромный хром в духе Notion, чернильно-индиговый акцент «каплями» в духе Obsidian. Цвет несут **данные** (суммы, статусы, эмодзи), а не хром; акцент никогда не используется как фон крупных областей. Новый дизайн должен развивать этот язык, а не заменять его.

### 8.1 Стек

Tailwind CSS v4 (токены через `@theme` в `src/styles/tokens.css`, тёмная тема — переопределение под `:root[data-theme="dark"]`); примитивы на radix-ui; иконки lucide-react; темы light/dark/system (`src/lib/theme.ts`, pre-paint против FOUC). CSS-модулей и CSS-in-JS нет — классы Tailwind прямо в JSX.

### 8.2 Цветовые токены

| Токен | Light | Dark | Назначение |
|---|---|---|---|
| `bg` | `#f7f6f4` тёплая «бумага» | `#141415` графит | фон приложения, сайдбар |
| `surface` | `#ffffff` «белый лист» | `#1e1e20` | контент |
| `surface-2` | `#f1f0ee` | `#27272a` | hover, пузырь юзера, бейджи |
| `line` | `#e8e6e2` | `#343437` | границы/разделители |
| `text` | `#37352f` тёплый почти-чёрный | `#e8e6e3` | основной текст |
| `text-secondary` | `#5f5e59` | `#a5a29b` | вторичный текст |
| `text-muted` | `#706f69` | `#8a8781` | приглушённый текст |
| `accent` | `#4f46e5` чернильный индиго | `#a5b4fc` перивинкл | только интерактив и мелкие маркеры |
| `accent-foreground` | `#ffffff` | `#1e1b4b` | текст на акценте |
| `danger` | `#a83a29` | `#e08573` | расход, ошибки |
| `success` | `#1a7f37` | `#79cf9d` | доход, подтверждение |
| `overlay` | `rgb(15 15 15 / .4)` | `rgb(0 0 0 / .55)` | подложка модалок |

Контраст выверен по WCAG: text/surface 12.6:1, accent/surface 6.3:1 (light) / 8.3:1 (dark), danger и success ≥ AA. Любые новые цвета обязаны держать AA в обеих темах.

### 8.3 Форма, тени, движение

- **Радиусы:** `sm` 6px · `control` 10px (кнопки, инпуты, чипы) · `card` 14px (карточки, диалоги) · `xl` 20px; пузыри чата и композер — `rounded-2xl`/`rounded-full`.
- **Тени:** light — почти плоские (`0 1px 2px` с прозрачностью 5–6%); dark — тонкий верхний inset-блик + мягкая глубина. Три уровня: `control` / `card` / `pop` (модалки, тосты).
- **Движение:** длительность по умолчанию 160ms, easing `cubic-bezier(0.2, 0.8, 0.2, 1)`; уважается `prefers-reduced-motion`.
- **Брейкпоинт** фактически один: `md` (≥768px) — водораздел desktop-sidebar ↔ mobile-tabbar. Контент чата — `max-w-3xl`. Safe-area снизу у таб-бара.

### 8.4 Типографика

Системный гуманистический стек (webfont не подключается): `ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, …`; mono для кода. Шкала ~1.2 с line-height «дышит под чат»:

| Уровень | Размер / межстрочный | Роль |
|---|---|---|
| `2xs` | 11/14 | счётчики, бейджи, микро-заголовки секций (uppercase + tracking-wide) |
| `xs` | 12/16 | вторичное, мета |
| `sm` | 14/22 | **рабочая лошадка UI** |
| `base` | 16/24 | текст чата |
| `lg`–`3xl` | 19–33px | заголовки диалогов и экранов |

Веса: `medium` (кнопки, заголовки строк, суммы), `semibold` (заголовки диалогов, логотип). Все числа и суммы — `tabular-nums`.

### 8.5 Иконки

lucide-react; размеры пропом: **16** — основной (строки, кнопки), 14 — мелочь, 18 — навигация/шапка, 32 — empty states. Декоративные — `aria-hidden`. Соответствия: `MessageSquare` чат, `FolderOpen` обзор, `ArrowLeft` назад, `ArrowUp` отправка, `CheckCircle2`/`Circle` статус задачи, `Loader2` спиннер.

### 8.6 AppShell и навигация (как реализовано)

- **Desktop (≥md):** постоянный левый сайдбар `w-60` на `bg` («бумага»), контент на `surface» («белый лист») — зоны читаются тоном, без разделительных линий. В сайдбаре: разделы, секция «Закреплённые», «Настройки» внизу.
- **Mobile (<md):** нижний таб-бар с safe-area; активный таб — акцентный цвет иконки и подписи.
- Активный пункт сайдбара — `bg-surface-2`; бейдж retry-буфера на «Чат» — красный кружок `text-2xs`.
- Push-стеки на zustand с persist: по стеку на таб, повторный тап по активному табу сворачивает до корня; настройки пушатся поверх активного таба.
- Шапка каждого экрана: sticky, `h-12`, полупрозрачная `bg-surface/90` + backdrop-blur, тонкая нижняя граница; «Назад» — ghost-иконка при глубине > 0.
- `<main>` — единственный вертикальный скролл-контейнер приложения.

### 8.7 Библиотека примитивов (`src/ui/`)

Button (primary индиго / ghost / outline; размеры sm, md, icon 32px; focus-ring `accent/60`) · Card (`rounded-card border-line bg-surface shadow-card`) · Badge (default / danger / accent, pill) · Chip (с удалением) · Checkbox (radix, 20px, checked → индиго) · Dialog (по центру, `min(92vw, 28rem)`, shadow-pop) · Sheet (боковая, `min(85vw, 20rem)`) · Input (focus → `border-accent`) · Tabs (подчёркивание `border-b-2 border-accent`) · Toast (снизу-справа, авто-dismiss 4s) · Spinner · Skeleton (`animate-pulse`) · EmptyState (иконка 32px + title + hint + action).

### 8.8 Фирменные приёмы (сохранять)

- **Списки без разделительных линий:** строка — скруглённый ряд `rounded-lg px-2.5 py-2`, hover `bg-surface-2`, зазор 1px. «Живая строка сущности»: слева эмодзи/тип-глиф в 20px-колонке, в центре title (у done — зачёркнутый muted), справа типизированная мета (срок / сумма / дата).
- **Асимметрия чата:** пользователь — тихий серый пузырь справа (`bg-surface-2`, `rounded-2xl rounded-br-md`, макс 75%); ассистент — **без пузыря**, текст и карточки прямо на листе (приём Claude/Notion AI), макс 92%. Индикатор печати — три пульсирующие точки.
- **Карточки в чате:** «тихая сетка подпись: значение» на subgrid, `text-xs`, значения `tabular-nums`; заголовок кликабелен, hover → индиго.
- **Композер:** плавающая капсула `rounded-2xl` с `shadow-control`, без верхней разделительной линии; focus-within — индиговая обводка; круглая кнопка отправки на акценте.
- **Цвет в данных:** суммы `danger`/`success` со знаком, точка приоритета у задач, эмодзи сущностей — при монохромном хроме.

## 9. Технические рамки для дизайна

- **PWA**, mobile-first, но ежедневно используется и на десктопе — обе раскладки полноценные (нижний таб-бар ↔ сайдбар, водораздел 768px).
- Стек web: React 19 + Tailwind CSS v4 (токены через `@theme`) + radix-примитивы + lucide-иконки; светлая и тёмная темы обязательны, контраст ключевых пар ≥ WCAG AA в обеих.
- Ответы AI приходят целиком (без стриминга токенов) — состояние ожидания должно жить с этим достойно.
- Деньги — рубли по умолчанию, формат «12 430 ₽», расход красным со знаком −, доход зелёным с +.
- Язык интерфейса — русский.
- Никаких модалок для views; допустимы для подтверждений и выбора.
