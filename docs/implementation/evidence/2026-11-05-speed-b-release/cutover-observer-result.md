# Cutover observer, один нейтральный контроль

Входной пакет `00f5ee22842b4524bf4d7c97d6a54f990de823f7b3bd2e92860c3f067b017101` сохранён в `cutover-runner-before-observer`. Новый пакет `b07dd775d905938aab48b5dd96b15130086bfc3f55b1a8aa95d788cb88e6e22d` меняет наблюдатель в scratch runner, добавляет общий observer и отдельный контроль. Точный `cutover-runner.observer.diff` описывает дельту. Product, артефакты и DB/DSN/процессные ограждения не редактировались.

Наблюдатель регистрирует token/sequence latch до навигации. Событие остаётся в памяти исходного документа и может быть доставлено консолью после возврата. Для подтверждения BFCache требуются реальные pagehide/pageshow, оба persisted=true, в исходном документе с тем же token. Отсутствие такой пары даёт uncovered статус. Нейтральная вторая навигация не объявляется дополнительным доказательством сохранения скрытой страницы. Основной held-N путь больше не зависит от немедленного console `find`.

**Ровно один observer-only запуск**, `/private/tmp/orbis-cutover-observer.UG0WSp`, завершился exit 0 на Chrome/156.0.8078.80. Контроль посещает две нейтральные loopback HTML страницы. Он не импортирует App, не подключается к tRPC, Auth или БД. Utility/process/pipe/close код скопирован дословно из reviewed runner и проверен по отдельным хешам срезов, общая логика наблюдателя используется обоими.

Пара доказательств принадлежит token `314adfcc-946d-4855-b631-e733a17b713d`: seq 2 pagehide persisted=true, seq 3 pageshow persisted=true. Латчи приняли эти события, а readonly память восстановленного документа подтвердила ту же пару. Никаких записей storage или тестового legacy writer нет. После завершения `context.close()` проверены событие закрытия и исчезновение всех десяти накопленных process identity. Root PID 93573, start `Thu Nov 5 13:17:30 2026`. Фактические флаги Chrome содержат pipe и не содержат отключения sandbox или BFCache. Остальные defaults и защита egress сохранены.

Этот контроль доказывает наблюдатель на нейтральных документах. Реальное b5 приложение может иметь другие условия BFCache eligibility. Нового N/P или повторного browser контроля после этого результата не было. Прежние RED не переписаны. Сырые данные и хеши находятся в `cutover-observer-control-evidence/`. Пакет ждёт source rereview до следующего окна.
