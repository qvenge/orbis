# Повторная сверка локального restore runner

**Одобрено по исходникам для перечисленных локальных фаз после передачи окна.** Девять файлов пакета `564ad8a5d067e14aa3c238741270ef0d1b8ee8c49b75ad2be1a17b3f37edbed5` совпали с манифестом. План `ecbce67513b187c27e4d398d1c7856a38fdd06de7a80ac2f7607481af8e0bc65`, runner `cda38b49f7359b16b5f6adf06bffcceb123d5be47ef780b60f3072b187ce46c0`, контейнерная дельта `63a2f6e54e154094440e6dbc9d726185e11d3f86d47904710ef54cd648082bad`. [Манифест](logical-restore-container-packet.sha256), [runner](logical-restore-container-runner/run-container.sh).

- Режимы имеют точный allowlist и отдельный фазовый handoff. SOURCE/TARGET различаются по полному Docker ID, имени, label, локальному порту и system identifier. Исполняется PG17.6+ CLI внутри выделенного контейнера через Unix socket, с фиксированными базой/ролью, очищенным окружением и паролем по stdin. `current_user`, `session_user` и socket подтверждают фактический контекст подключения. При local trust они не служат проверкой пароля. Runner сравнивает строку `.Config.Image`, поэтому при выделении зафиксировать фактический immutable `.Image` обоих контейнеров и локальный Docker daemon/context отдельно.
- Source-dump вызывает неизменённый `scripts/backup.sh` по собственному socket DSN после source identity. Нужный host PostgreSQL CLI не требуется. Фиксированные staging-файлы полностью копируются до подключения и проверяются на хосте и внутри контейнера. Stock import и rebase выполняют первый SQL guard и проверку socket на той же psql-сессии с `ON_ERROR_STOP` и одной транзакцией до данных. Output copies ограничены именами внутри принадлежащего пользователю каталога 0700, контрольные SHA сверяются после копирования.
- `render-acl` выпускает только SQL из отдельно выбранного ACL TOC. `acl-replay` принимает отдельный просмотренный exact hash и guard. На handoff прочитать фактический SQL целиком: ожидаемые object/column/default ACL, штатный безопасный пролог и ограничители `\restrict`/`\unrestrict`. Reconnect, явные transaction boundaries, shell и прочие операции вне ACL исключаются из рассматриваемого файла, чтобы проверенная psql-сессия не подменялась. Создание контейнеров, catalog repair, синтетический seed, scheduler, evidence probes и client cutover остаются отдельными согласованными шагами.
- Rollback-control и rebase получают точные старый floor и уже committed witness. Условие свободной цели, lock, предсказуемый intentional failure и атомарное изменение только производной ленты сохранены. Фактический RED rollback должен оставить feed и floor в исходном состоянии. Допуск клиентов и release STOP не выводятся из проверки runner.

Актуальный cutover-план `45ccb03ee57730b3812cf2466a70e72780d1e6d8d695f4da1ea46e580a8c2083`, дельта `9a391b9a6b2b74403e6efbd46a1cc017b94701f0f0710086de78889d9759b83b` закрывают два последних source-замечания. Оба старых body POST блокируются до upstream и до завершения старого процесса. Точный локальный Auth origin используется только выделенным fixture или перехватывается внутри одноразового browser context. Ранее рассмотренные CAS, PID и controller guards сохранены. [План перехода](legacy-cutover-rehearsal-plan.md).

Запусков runner, Docker, PostgreSQL, Chrome, сборки или тестов в этой сверке не было.
