# Повторная сверка SQL восстановления и cutover runner

## Каталог и ACL локальной цели

**Одобрены точные предложения для ограниченной фазы catalog/ACL и low-XID witness.** Проверены 73 артефакта первого этапа по манифесту `4e1b87cf2642bd40adfdd7cf2821bbafff6ff411503f7580e975cd05ef9b372b`. Отчёт `40286078d7c0e0de53aea4ab2b5c31c633aa7ccc4d22aa69280465a750053a14`. Stock dump и прежний ACL replay действительно оставили бизнес-данные совпадающими, перенесли floor 5250/84 события при target xmin 995 и воспроизвели отсутствие доступа 42501, роли, owner и cron. Ни успешный импорт, ни повтор Drizzle не починили каталог. Local Unix trust подтверждает связку сокета, БД и роли, без проверки пароля. [Первый этап](logical-restore-phase-one-report.md).

- `catalog-repair-proposal.sql` SHA `ada90f29f127d52d74fd39faa1d1548c78e944f30bdd738c151269b6cc8ecf78` восстанавливает отсутствующую capture role с исходными flags, owner public и definer, extension и две задачи. Все остальные владельцы приложения совпадают. Не восстанавливается только неиспользуемая edge `supabase_admin → orbis_change_feed_owner` без ADMIN/INHERIT/SET. Оба тела `cron.schedule` совпали с миграциями 0024/0027 и MD5 фактических source jobs. Содержимое функции захвата, RLS/политики, строки ленты и бизнес-данные предложением не меняются.
- `acl-proposed.sql` SHA `9e63ef542939dd175f252bf6f97ddbee13eeb5fa0c33f51caf82d66befc7b512` совпадает с PG17-generated ACL после удаления единственного добавленного `GRANT USAGE ON SCHEMA public TO PUBLIC`. Независимое сравнение с фактическим исходным каталогом совпало по schema/object, column и default grants. Проверены 164 grant, 24 default grant и три закрытия PUBLIC EXECUTE. В target исходно отсутствовали explicit app relation/default ACL, а три частные функции имели implicit PUBLIC EXECUTE. Только 11 стандартных прологов и парные `\restrict`/`\unrestrict`, без reconnect, завершения транзакции, shell или постороннего SQL.
- После того же in-session target guard и только в выданном окне требуется проверить фактический каталог/effective privileges, два графа и закрытый write/helper доступ. Затем взять реальный committed target XID ниже импортированного floor и показать оба перехода reconcile. Ревью не открывает rollback/rebase, scheduler, браузерный перевод или prod. Предложенный SQL самим ревью не исполнялся.

## Cutover runner

**Пять ранее отмеченных направлений закрыты по исходникам для первой изолированной попытки.** Пять файлов манифеста `da56c86fc45fb487f975fb2ecbf4da2be4e39dddb710953638a8be7ef348a938` совпали. Истинная дельта `34a40e1fc3dbaadd5578e1d7b7737abd6f996234dffa5965cf92656eae793fe4`.

- Root handoff закрепляет сценарий, точный порт 54344/54345, container ID/image, system ID и два манифеста. DSN query overrides запрещены. Роль и кластер проверяются на живом admin соединении до seed и миграции; launcher проверяет restricted runtime login и не получает admin DSN. При выделении надо фактически подтвердить, что TCP `postgres` в pinned image является SUPERUSER и может прочитать system identifier. На restore-стенде для этого использовался `supabase_admin`. Если предпосылка не выполнена, runner останавливается. `orbis_app` при локальной подготовке должен сохранить отсутствие membership в elevated roles.
- Обычная загрузка различает `ordinary-worker-controlled` и `fresh-http-later-controller`. Успешный 0.7 tRPC response привязан к наблюдаемому main frame и новому журналу через sequence header. Прежний assisted/bootstrap не может удовлетворить этот барьер. Driver 412 и опциональный поздний browser 412 получают разные записи.
- D2 проверяет forwarded исходный client UUID и canonical payload, реальный ACK с тем же ID, семантические поля строки и единственность записи и journal action по отдельной синтетической категории. Старый POST остаётся за pre-upstream gate, body CAS и pending/consent проверки прежние.
- Старый build использует allowlisted окружение и pinned origin Auth. Точный текущий dist скопирован побайтно в чистое дерево, входные манифесты и inventory повторно сверяются. CDP Auth, прокси-изоляция, BFCache, Workbox, UI selectors и реальный parser остаются предпосылками первого запуска и могут дать отдельный RED. Браузер и БД в этой фазе ревью не запускались.
