# Сверка исполняемого cutover runner

Проверен пакет из четырёх файлов, SHA-256 манифеста `ae32afc970f3f2512c9e7d88ff7f87ad5667596ea18f3c0aa6f6f4aee98266d1`, по плану `45ccb03ee57730b3812cf2466a70e72780d1e6d8d695f4da1ea46e580a8c2083`. Все хеши совпали. Сверка только по исходникам, без синтаксического запуска, БД, Chrome, сети и сборки.

## Перед первым запуском

1. **Ограждение DB identity.** `rehearsal.ts:17–27,385,457,849` проверяет loopback, запрещённые порты и имя lane, но не проверяет protocol, URL query overrides, точный выданный порт и фактические роли. Runner пишет `auth.users` и запускает миграцию. Нужны переданный root точный порт/имя/expected admin и runtime user, запрет неожиданных параметров URI, actual identity и system identifier на административном соединении до записи. Для настоящего upstream проверить restricted runtime login на фактическом соединении. Не передавать admin DSN в server child без необходимости, поскольку он нужен отдельному мигратору. Ошибки разбора или драйвера не должны печатать полные DSN.
2. **Обычный старт и worker.** `entryEvidence:617–650` логирует `response.fromServiceWorker()`, но допускает false/отсутствующий response. `versionSeen` ищет 0.7.0 по всему журналу, включая assisted bootstrap предыдущего процесса. Для обещанного ordinary worker-controlled старта проверять `fromServiceWorker()` самой ordinary навигации или отделить статус свежей обычной сетевой загрузки с последующим контроллером. Привязать 0.7.0 к конкретному новому документу/навигации, используя границу журнала и page-observed request. Exact HTML, новый census и precache hash уже полезны и сохраняются.
3. **D2.** Проверка исходного payload в очереди есть, но `SELECT count(*) WHERE id = queuedId` по PK лишь показывает существование одного ID. Привязать действительно переданные current fast-path операции к исходному UUID и смысловому payload, затем проверить свойства принятой строки и отсутствие второй записи/действия того же синтетического ввода. Транспортный отказ b5 уже отдельно проверяется до upstream.
4. **Заморозка артефактов и окружения.** `artifacts.py` проверяет git blob SHA и accepted a0 dist, но `verify` рантайма доверяет переданным JSON. Зафиксировать и перепроверять exact SHA самих двух манифестов на handoff. Для старой сборки использовать явный список build env, так как команды снимают только три наследуемых VITE ключа. Проверенный Auth host и исходный b5 build scope остаются прежними.

## Уже выдержанные границы по исходникам

Один origin с реальными pinned Hono upstream. Narrow CDP interception обслуживает только local Auth, не заменяет tRPC и не использует Playwright route с глобальным отключением HTTP cache. Остальной трафик Chrome ограничивается одноразовым deny-proxy. Её фактическую работу и возможность контролировать localhost Auth ещё предстоит наблюдать.

Runner удерживает точные байты реального b5 HTML и освобождает bypass на том же held target до release. Поздний документ публикует собственный controller/protocol и старый Auth writer наблюдается отдельно от nav. До выполнения положительной ветки сохраняются PID/start и дерево потомков, проверяется выход, CDP disconnect и отмена удержанной навигации. N-факт `real-412` пока относится к driver запросу. Реальный 412 именно позднего browser target следует засчитывать только при отдельной записи в browser journal.

Old body и D2 события блокируются до upstream, на двух реальных draft fixtures, после выхода подтверждаются прежние серверные ревизии, затем два отдельных CAS создают расхождение. В current открытии проверяются точные draft doc/basis и отсутствие неявных body POST. Первый документ подтверждается по настоящей записи и ревизии, второй сохраняется до consent и остаётся без body POST. UI, BFCache, CDP Auth/proxy, Workbox cache и fast-path parser ещё не проходили первый запуск. Не считать управляемый assisted bootstrap первым обычным успехом или полевой процедурой.

Текущая оценка — **требуются ограниченные правки runner и handoff перед исполнением**. План перехода и принятый runtime этим не переоткрываются. Непроверенные операционные результаты не переносятся в постоянный runbook.
