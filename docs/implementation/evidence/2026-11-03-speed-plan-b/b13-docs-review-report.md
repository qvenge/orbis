# Б13 — адресные уточнения документов по общему ревью

Поверх снимка `five-docs-r6-r7-wording` изменены три файла. Архитектура §4.12 различает `W2 < floor` и `W2 >= floor` при курсоре ниже порога по `feed.ts`. §4.10 ограничивает четыре политики обычными изменяемыми графовыми таблицами и явно сохраняет SELECT-only ленту и порог по `0027_change_feed.sql`.

В §4.12 описана принятая вкладочная авторизация общего режима. `shared-session.ts` до создания SDK чистит унаследованные слоты, допускает повторное использование маркера только при reload и получении Web Lock, создаёт уникальный ключ и возвращает null-backend при отсутствии безопасного хранилища. `browser-lifecycle.ts` подставляет этот scope, при shared ON чистит прежнюю сессию, а `auth/storage.ts` использует изолированную память при null. Обычный режим этим описанием не изменён.

Runbook и pending называют оба эффекта `VITE_RESPONSE_PERSISTENCE=off`: обход восстановления в `query-responses.ts::restoreResponse` и отключение записи через `bindQueryResponses`. Чтение и запись нового формата черновиков остаются требованием. Runbook отдельно фиксирует локальный HTTP 0.6.0→412 с отклонённой записью и открытое требование сохранности реального ввода старой сборки/установленной PWA. CI, no-local-main, полевая граница и §4.3 STOP сохраняются.
