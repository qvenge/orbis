### Граница SSE и предел оценок

`httpSubscriptionLink` сидит в том же `@trpc/client/dist/index.mjs` (**15454 Б renderedLength**), где нужны HTTP/client factory/proxy/TRPCClientError. В закреплённой версии нет отдельного публичного subpath для httpSubscriptionLink. Подмена места вызова на dynamic import общего client entry сама по себе не гарантирует переноса его кода. Из `@trpc/server/dist/resolveResponse-*.mjs` реально отмечены `sseStreamConsumer`, `Unpromise`, `makeAsyncResource`, `makeResource` и using helper (**18787 Б renderedLength всего модуля**); `splitLink`/createChain **993 Б**. Это потолок на **целые смешанные модули**, часть которых нужна другим путям. `trpc.ts` целиком **8108 Б** содержит HTTP, provenance, cache, auth и undo; SSE-блок внутри меньше, отдельно здесь не измерен.

Даже если целиком прибавить эти три смешанных tRPC модуля к пяти исключительным веткам, получится **83207 Б pre-minify renderedLength**, плюс небольшой локальный SSE wiring. Это завышенная инвентарная оценка. Для масштаба текущие целые index и trpc имеют gzip−9/renderedLength **0,144 / 0,137**. При таком масштабе получится около **12 КБ**, без учёта новых границ и повторных импортов. Это ориентир, не измеренный выигрыш и не математический потолок gzip. Для 36,9 КБ из 83,2 КБ весь удаляемый набор должен дать ~44% gzip/raw до minify, втрое больше наблюдаемого масштаба обоих контейнеров. Подтверждения такому сценарию нет.

## Что удерживает остаток

Окончательный closure: index **135286 Б**, percent **47820 Б**, trpc **39198 Б**, query **28147 Б**, shared src **27858 Б**, DetailScreen **22541 Б**, dependencies **3925 Б**. Большие источники raw в index — React DOM (**452195**), auth-js (**162525**), freshness runtime (**28520**), browser lifecycle (**27230**). В trpc общем чанке держатся React Query adapter и HTTP, draft-storage (**16409**), draft-mirror (**11589**), input-slot (**7859**), query responses (**5572**) и body provenance (**4404**). Сам chunk name или вынесение общего кода в другой eager chunk не дают экономии closure. В query/shared расходятся статические пути для валидации, размещения, реестра и первого запроса. Пример предела module statistic: `registry/rule-fixtures.ts` сообщает **13548 Б renderedLength**, однако известные маркеры fixture отсутствуют в конечном `src-*.js`. Полную стоимость такого модуля нельзя кредитовать как выводимое из финального JS место.

Новых путей через уже ленивый chat/RunFeed/BodyEditor не найдено. Разрез Markdown был единственным измеренным вариантом порядка дефицита и не прошёл холодную заметку. Результат оставляет текущий guard красным. Решение по необходимости/цене новых функций возможно только на принятом Б11 и сопоставимых after-B/first-content замерах, с открытым обоснованием каждого изменения бюджета. До такого решения нет основания менять порог или вводить несколько отдельных lazy границ ради частичной экономии.
