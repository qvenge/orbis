# Б13-R6 · P2 · Ожидающий заголовок скрывает чужую правку от общей истории

При возврате в штатный `DetailScreen` с шаблоном только `{{body}}` принятый сетевой ответ содержал «Чужое имя Д». Это имя отличается от исходного «План», своей неопределённой отправки B и своей ещё ожидающей C. Runtime подтвердил raw D, а оптимистическая накладка сохранила видимый заголовок C. Общая стрелка тела оставалась активной, нативная глубина Tiptap была 2. Нажатие «Шаг назад» до ответа C действительно изменило открытый текст `тело`→`ownтело`, undo/redo 2/0→1/1. В следующие 1,2 секунды body HTTP не наблюдался. Доказано ошибочное локальное применение Undo, без вывода о серверной записи. После известного отказа C накладка снялась, D стало видимым, обе истории очистились. [Трасса](/private/tmp/orbis-b13-history-raw.DRFuxk/probe.log:79).

§7.5 rev6 требует сброса общего стека при чужом заголовке или теле до следующего нажатия. Совпадение raw B с ранее неопределённой отправкой действительно не доказывало автора в исходном сценарии. Новый D устраняет неоднозначность, сохраняя тот же причинный путь. В контролях собственная C уже принята сервером и совпадает с raw, один раз её HTTP ACK удерживается и один раз получен. В обоих случаях собственный Undo остаётся доступен и выполняет ожидаемый шаг. [Спецификация §7.5](/Users/birzhan/projects/orbis/docs/superpowers/specs/2026-09-29-speed-stages-0-1-design.md:636), [контроли](/private/tmp/orbis-b13-history-raw.DRFuxk/probe.log:90).

`BodyBlock` для шаблона без заголовка наблюдает `entity.title` из RecordHost. Это значение после Б8 включает pending-проекцию. Смена raw под неизменившейся C поэтому не достигает `observeTitleValue`, хотя runtime уже принял новую публикацию. `TitleEditor` также наблюдает отображаемое значение. Факт ошибки подтверждён на body-only, родственный путь с заголовком требует контроля и сам по себе этим тестом не осуждён. Источник регрессии — стык Б8, где `QueryCache` показывает optimistic projection поверх принятого raw, с потребителем истории из А. Базовая проверка `actual cold BODY current basis` существовала уже в `b5abb7fe`. [BodyBlock](/Users/birzhan/.codex/worktrees/853d/orbis/apps/web/src/features/entity-detail/record-blocks.tsx:121), [TitleEditor](/Users/birzhan/.codex/worktrees/853d/orbis/apps/web/src/features/entity-detail/NativeRow.tsx:193), [публикация](/Users/birzhan/.codex/worktrees/853d/orbis/apps/web/src/lib/freshness/runtime.ts:1032).

Подходящая область правки — владелец Б8 и узкий стык истории с принятым scoped raw canonical detail. Проверка должна различать действительно новую чужую основу, совпадающее собственное pending/ACK и повтор прежней сырой основы под накладкой. Нельзя подавать каждое raw значение в существующее сравнение с показанным заголовком, поскольку это сделает прежнюю основу «чужой» во время своей отправки. Сброс истории должен сохранять показанный оптимистичный заголовок, грязный ввод, экземпляр редактора и данные его тела. Для R6 требуется независимый повтор реального клика до settlement C, а также сохранение pending/ACK и неподтверждённых дисковых контролей.

В подготовленном `b13-web-consolidated-review.diff` семейство `early remount before old refusal clears foreign basis` после `acceptedDetailTitle(...)=foreign` требует показанное «План Б» и `canUndoStep(...) === true`, а при `bodyTop` ещё и `undoDepth === 1`. Первое ожидание проверяет правильную scoped проекцию. Два ожидания истории нельзя закреплять для варианта raw «Чужое имя», которое отличается от собственной ожидающей B: при принятом чужом raw применяется тот же контракт §7.5. Вариант raw «План Б» совпадает с ожидающей отправкой, и до дополнительного доказательства авторства его надо сохранять как отдельный контроль. Этот разбор относится к ожиданиям патча. Независимая проба фактического Undo проводилась на body-only, а не на смонтированном title editor.
