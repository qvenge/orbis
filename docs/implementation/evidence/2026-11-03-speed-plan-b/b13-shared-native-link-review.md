# Б13-R5 · P2 · Ссылка записи из общего режима оставляет идентификатор в истории браузера

В Chromium 156.0.8078.80 после штатного включения общего режима средняя кнопка и Cmd-click на строке реального поиска открыли две новые вкладки на `/r/<uuid>`. Обе показали экран входа с `history.state === null` и `window.opener === null`. После закрытия браузера оба UUID остались в таблице `urls` нативной SQLite History. Содержимое записи и авторизация в новые вкладки не перенеслись. В обычном режиме контрольная средняя кнопка открыла адрес записи, а обычный клик в общем режиме открыл запись в той же вкладке с URL `/` и непрозрачным `history.state`. Идентификатора обычного shared-перехода в SQLite не было. [Сырой журнал](/private/tmp/orbis-b13-shared-links.vGH1cO/native.log).

Срез — штатный production dist кандидата `882bd444e87793d4b4c6c9a1e9b64afe14d93b6c`, оболочка `index-C8QvvH3-.js`, SHA-256 HTML `4a21b1b90996b48211d7e0104d07fd7815b8b53ad1b49e4747be37c817d9b9a0`. Все 11 проверенных исходников ссылок, поиска, auth, истории и lifecycle побайтно совпадают с `d0af7420e467675e2cdff7dc23c5b40a6c2b17cd` и снимком reset fix2. Сборка не повторялась. Использованы собственный временный профиль, локальный синтетический tRPC, тестовый HTTP-ответ auth-js и штатный production service worker для census. Профиль удалён после чтения SQLite, личные данные и приложение в production не использовались. `bun run /private/tmp/orbis-b13-shared-links.vGH1cO/probe.ts`, Bun 1.2.7, exit 1 на ожидании непрозрачного URL. ## Причинный путь и граница требований

Б7 хранит shared-навигацию в памяти. `urlNow` возвращает `/`, а snapshot публикует в `history.state` только `orbisNav`, id и lineage. Исходное ревью Б7 отдельно установило, что запись UUID или поискового текста в URL нарушает это свойство даже при непрозрачном state. Б10 дал ссылкам настоящие адреса для штатных действий браузера. `RecordLink` оставляет неосновное нажатие браузеру, а controller формирует ссылку с UUID без проверки shared. Новый анонимный документ возвращается из `ScopedAuthProvider` с LoginScreen до монтирования App, поэтому shared SPA-правило адреса к этой навигации не применяется. Позднее изменение адресной строки само по себе не доказывает удаление первой записи из SQLite. [Действующая shared-история](/Users/birzhan/.codex/worktrees/853d/orbis/apps/web/src/app/history.ts:194), [RecordLink](/Users/birzhan/.codex/worktrees/853d/orbis/apps/web/src/lib/entity-ref/RecordLink.tsx:62), [controller](/Users/birzhan/.codex/worktrees/853d/orbis/apps/web/src/lib/entity-ref/record-link-controller.ts:76), [LoginScreen до App](/Users/birzhan/.codex/worktrees/853d/orbis/apps/web/src/auth/AuthProvider.tsx:100), [предыдущее замечание Б7](/Users/birzhan/.codex/worktrees/853d/orbis/.superpowers/sdd/2026-11-03-speed-plan-b/b7-review.md:33).

Это новый адрес, который само текущее приложение подставляет в нативное открытие, без вставленной пользователем внешней ссылки или прежней навигации. Предпосылка чистого перехода со старых клиентов здесь выполнена. Отдельный жест «Скопировать ссылку» намеренно формирует полный адрес для передачи и остаётся отдельной поверхностью. Спека §6.5 требует нового входа и режима «не хранить данные на устройстве». План Б7 уточняет memory-only навигацию, Б10 сохраняет обычную нативную доступность, а текущая архитектурная документация обещает скрыть внутренние адреса из истории. Устранение требует совместить эти два пути, не ослабляя нормальный native open или явное копирование. [Требования Б7](/Users/birzhan/.codex/worktrees/853d/orbis/.superpowers/sdd/2026-11-03-speed-plan-b/b7-brief.md), [требования Б10](/Users/birzhan/.codex/worktrees/853d/orbis/.superpowers/sdd/2026-11-03-speed-plan-b/b10-brief.md), [явное копирование](/Users/birzhan/.codex/worktrees/853d/orbis/apps/web/src/features/entity-detail/DetailScreen.tsx:378).

Markdown внутренних ссылок использует тот же RecordLink с исходным `href`. Нативный Link mark редактора сохраняет `href` после ACK и пропускает модифицированные нажатия. Это связанные пути по исходникам, без нативных утверждений сверх проверенной строки поиска. Проверка исправления должна охватить их вместе с клавиатурным открытием в той же вкладке, отменой предзагрузки и нормальными модификаторами.
