## F-I1 — сравнение токенов

Один сценарий, реальная Tiptap правка, один held send, тот же жест «Сделать страницей». В обоих вариантах до release виден тост и пачка не ушла, после release ACK `00000000-0000-4000-8000-000000000125` / tx `1` / revision `2` виден в mutation cache, вторая отправка и 409 отсутствуют. Измеряли точный WeakMap token запроса, slot текущего черновика, сравнение полных bodyDoc и emergency copies.

| Сценарий | До жеста | После жеста до ACK | После ACK |
| --- | --- | --- | --- |
| Старый unbound harness | submitted A = slot A, rev1 | slot B, doc идентичен A, rev1; send всё ещё один | B остаётся unacked, чужой токен не снят по ACK A |
| Управляемый persistent writer, emergency Web Storage, без response persistence в harness | submitted A = slot A, rev1 | тот же A, один send, один pending emergency copy | тот же A acknowledged в памяти и единственной emergency copy, doc точный |

`body-gate.ts::settleBody` вызывает flush, `useBodySave.ts::save` stage-ит до single-flight return. `draft-storage.ts::saveDraft` в unbound ветке всегда выделяет новый slot, `draft-mirror.ts::stage` дедуплицирует тот же объект, revision и rejected. `useEntityDetail.ts::settleBodyDraft` сверяет точный submitted token, поэтому B не стирается ACK A. Browser lifecycle при доступном input backend устанавливает managed metadata независимо от response cache. `query-responses.ts::bindQueryResponses` в off-режиме ставит sink, который не пишет response; подтверждение в input mirror сохраняется. При включённом cache `acceptBody` вызывает `finishDraftSlot` для точного A только после durable acceptance и повторной проверки current ticket/session. Последние две ветви проверены по исходнику. В локальном jsdom probe использованы реальный managed input writer и emergency codec, runtime без binding response sink/IDB, поэтому это доказательство идентичности/retained ACK, а native cache-on/off и обычный durable retirement ещё впереди.

Probe `apps/web/src/features/page/b13-page-flight-slot.probe.test.tsx` внутри указанного архива. Первый контрольный запуск собрал все шесть checkpoints, но завершился exit 1 из-за `release` вне scope в finally диагностического кода. Сохранены source+raw первого запуска. В повторе переместили декларацию перед try, все assertions неизменны, exit 0, 2 PASS / 42 skip. Точные значения и номера TX в `b13-web-flight-slot{,-rerun}.ndjson`. Нулевой черновик остаётся подходящей проверкой durable retirement. Для held-flight в tracked тесте предложен управляемый writer с точным неизменным token, bound disabled response sink, проверками pending → acknowledged в emergency storage, одним send и нулём batch. Нужен финальный native normal/off контроль. Это устраняет неверное состояние стенда без ослабления exact-token защиты и без изменения продукта.
