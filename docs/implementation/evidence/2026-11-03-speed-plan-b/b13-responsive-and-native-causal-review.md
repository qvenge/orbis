## Две причинные проверки сохранения закрыты

Нативная проба на exact a0 normal dist использовала настоящее видимое тело, существующий thread ID, его сообщения и поле ввода бокового чата. За 30 секунд фактического набора — 43 вставки, 6 autosave POST, 0 `entity.get` и 0 чтений чата. При строго удержанном ответе и в последующие шесть секунд без ввода также не наблюдалось этих чтений. Транспортные категории учтены отдельно. Это один функциональный контроль счётчиков, без вывода о latency или общем after-B.

Для отдельного строгого сохранения барьер целевых GET включён до ввода, ранее начатые запросы дренированы, исходные серверная и дисковая ревизии совпали. Настоящий сервер закоммитил TX55042 и сформировал HTTP 200 с правильными ID, полной bodyDoc и ревизией 8. Пока этот ответ удерживался, на диске оставалась rev7 и был найден точный input token с basis7. Отпущен только ACK. Полная bodyDoc и rev8 стали durable, а тот же nonce исчез из native слота. Барьер GET отпущен после обоих фактов. В этом окне целевых GET вообще не было. Причинная проверка отделяет запись по ACK от возможного перечитывания.
