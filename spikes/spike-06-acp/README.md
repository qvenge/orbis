# Спайк 06 — ACP: может ли Orbis рулить локальным агентом под подпиской

**Статус: закрыт. Ответ — да, одной связкой из трёх.**
**Код здесь выбрасываемый.** Он написан, чтобы увидеть провод, а не чтобы жить.

Дата: 2026-08-13. Машина: darwin x86_64, Claude Code 2.1.231, codex-cli 0.147.0.

## Вопрос

Может ли внешний процесс (в перспективе — Orbis) прогнать настоящую задачу через
локально установленного агента по ACP — под подпиской пользователя, без API-ключа —
и получить обратно поток, достаточный для ленты прогресса и для ворот подтверждения?

## Как проверялось

`probe.ts` — клиент ACP на сыром ndjson JSON-RPC (SDK намеренно не использован, чтобы
видеть провод). `fake-orbis-mcp.ts` — игрушечный MCP-сервер в форме Orbis: отдаёт спеку
требования REQ-042 и принимает отчёт о ходе работы.

```
bun install
env -u ANTHROPIC_API_KEY ORBIS_MCP=stdio ACP_MODE=default \
  ACP_TASK="Получи спеку REQ-042 инструментом orbis_get_spec, выполни, отчитайся через orbis_report_progress" \
  bun probe.ts node_modules/.bin/claude-agent-acp
```

Сырой провод обеих сторон пишется в `raw-<адаптер>.log`.

## Что выяснилось

### 1. Подписка — да, подтверждено уликой из потока

Прогон без единого ключа в окружении. `initialize` вернул пустой `authMethods`
(«аутентификация не требуется») — адаптер подхватил логин Claude Code из Ключницы.
В потоке приехало:

```json
"_claude/rateLimit": {
  "status": "allowed", "rateLimitType": "five_hour",
  "overageStatus": "rejected", "overageDisabledReason": "org_level_disabled",
  "isUsingOverage": false
}
```

`five_hour` — окно подписки, а не API-биллинг. Списалось из подписки.

### 2. Поток годится для ленты прогресса

Виды `session/update`, встреченные вживую: `tool_call`, `tool_call_update`,
`agent_message_chunk`, `usage_update`, `available_commands_update`,
`config_option_update`, `session_info_update`, `user_message_chunk`.

`usage_update` несёт токены, размер окна и оценку стоимости:
`{"used":29047,"size":1000000,"cost":{"amount":0.181454,"currency":"USD"}}`.

`plan` объявлен протоколом, но на этих задачах не приезжал.

### 3. Ворота — на уровне протокола, своей обвязки не нужно

В режиме `default` (Manual) КАЖДЫЙ инструмент проходит через
`session/request_permission` с вариантами `reject_once / allow_once / allow_always`;
ответ клиента управляет исполнением. В режиме `auto` решает классификатор модели.
Трёхуровневые ворота HARD/SOFT/AUTO ложатся на это один в один.

### 4. Полный круг «спека → работа → отчёт» замкнулся

Агент вызвал `mcp__orbis__orbis_get_spec`, получил спеку, выполнил её, **сам проверил
приёмочный критерий** (`wc -l`, `grep '^Здравствуй'`) и отчитался через
`mcp__orbis__orbis_report_progress`. 35 секунд, 3 запроса разрешения.

### 5. Ловушки, которые обошлись бы дорого

- **`type: "acp"` для MCP молча игнорируется.** Протокол объявляет транспорт, где
  MCP-сервер предоставляет сам клиент по ACP-каналу (`mcp/connect`/`mcp/message`) —
  идеальная форма для Orbis. `claude-agent-acp` 0.66.0 принимает параметр **без ошибки**,
  но инструменты не появляются; `codex-acp` честно объявляет `"acp": false`.
  → Orbis ОБЯЗАН читать `mcpCapabilities` из `initialize`, а не надеяться.
  Рабочие сегодня транспорты: `stdio` и `http`.
- **`fs/*` и `terminal/*` агент не делегирует**, хотя капабилити объявлены — работает
  файлами сам. Orbis увидит файловые операции только как `tool_call`.
  → Изоляцию даёт рабочий каталог и режим, а не протокол.
- Ответ на `session/request_permission` — `{outcome: {outcome: "selected", optionId}}`,
  вложенный `outcome` в `outcome` легко проглядеть.
- Путь к адаптеру надо резолвить до абсолютного: `cwd` процесса — воркспейс.

## Вывод для архитектуры

Orbis **не может** рулить агентом из Render напрямую: адаптеры process-local, а
документация Codex App Server прямо предупреждает, что это не HTTP API для веб-приложений.

Нужен **локальный раннер** на машине разработчика: держит воркспейс, спавнит адаптер,
стримит Orbis поток по WS, принимает решения по воротам, поднимает Orbis-MCP по stdio.
Токены подписки при этом не покидают машину — Orbis их не видит вообще, что снимает
юридический вопрос про подписку в стороннем продукте целиком.

Полезное на будущее: в `@agentclientprotocol/sdk` 1.3.0 есть
`experimental/http-client`, WebSocket и SSE — то есть канал «браузер ↔ раннер»
не придётся изобретать.
